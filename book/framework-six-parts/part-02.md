## 05 统一模型消息与工具协议

### 进入条件

读者已经有Rust单次工具往返的等价行为，理解Result和JSON序列化。02已有局部的调用ID配对和错误回传，04保留了这些行为；本章把它们统一成可供循环和不同适配器使用的内部合同。本章新增的模型工具仍限受控读取；04 保留的人工确认写入路径不扩成通用写工具。尚无自主多轮调度或 MCP 协议。

### 问题与失败现象

模型消息、工具结果和内部事件各用一套字段，导致第二轮无法知道结果属于哪个调用，或把工具失败改写成空文本。多调用响应还可能只按数组位置配对。第一部分的越界路径必须回传真实结构化错误；本章先统一内部语义，不把 MCP/Anthropic 等外部格式当作核心合同。

### 核心概念

固定 `Message{role,content,tool_calls,tool_call_id}`、`ToolCall{id,name,arguments}`、`ToolResult{tool_call_id,ok,output,error}` 和 `ModelTurn`；用调用 ID 配对，success/error 同时保留。serde 的 `toolCallId` 是 wire 命名映射。适配器负责外部转换，核心只消费统一类型。

### 小节安排

1. **画出一轮消息序列**：展示 user、assistant tool calls、tool、assistant answer 的顺序。
2. **实现调用 ID 配对和结构校验**：拒绝未知工具、坏参数和重复 ID。
3. **把工具失败变成下一轮可读消息**：保留错误类别与原始调用，不造成功输出。
4. **隔离外部适配器**：用 OpenAI 兼容和离线回放说明转换边界，不实现 MCP。

### 贯穿示例

当前 Hello World 回放先提出 `read_file`，结果带 `read-1`；第二轮的回答必须能引用该 `tool_call_id`。越界样本的 `../outside` 返回 `ok:false,error:path_invalid`，消息仍带 `read-1`。一轮返回两个相同语义调用时，二者 ID 不同但动作身份可后续规范化；消息数组顺序不替代 ID 配对。

### 实现增量

计划在 `rust/src/rein/mod.rs` 冻结拥有型消息、工具、错误和 `ModelAdapter` trait，在 `rust/src/rein/adapter.rs`（待设计）放 provider/replay 转换。加入 `validate_model_turn`、`append_tool_result`，禁止核心直接接受任意 JSON。错误分类暂用 `path_invalid/model_error/empty_final/...`，与 04 映射表保持一致。

### 验收设计

正常检查一条和多条调用都能按 ID 生成正确 tool 消息，下一轮可读取结果。失败覆盖未知工具、坏参数、重复 ID、缺 tool_call_id、工具失败和 provider 无效响应；程序保留原始调用并停止或回传明确状态。回归第一部分固定的读取、拒绝、接受与验证样本须通过同一协议，尚未执行新章检查。

### 产物与练习

产物是内部消息 schema、适配器边界说明、错误映射和 F05 计划快照。练习要求交换两个工具结果数组顺序，确认 ID 配对不变；再让同一调用 ID 重复，检查拒绝。完成标准是能区分消息、事件和外部 wire，不以字段名称相似证明兼容。

### 交接

交给 06 的是可追加消息、严格工具结果和 adapter trait；06 可在不改协议的前提下循环请求模型。第一部分固定样本仍须回归，C05 的迟到/循环样本留给 07–08。

### 复用与证据

复用 [05-rust.md](../../docs/chapters/05-rust.md) 的 `Message`、`ToolCall`、`ToolResult` 与 `toolCallId` 解释，以及 `rust/src/rein/mod.rs`、`rust/src/rein/loop.rs` 的已有实现。当前代码可能已实现更大范围能力，不能假定教材 F05 顺序成立；外部格式适配和新快照计划新增、尚未核实。

## 06 写出核心 Agent Loop

### 进入条件

读者有统一消息协议、受限 read_file、回放 adapter 和第一部分固定样本，可运行一次工具往返。search_files由本章新增，并沿用02的范围、字节数和超时限制。尚未有自主连续循环、完整预算策略和取消；事件先做最小观察，08再补运行期间的终端展示与控制。

### 问题与失败现象

只执行模型第一次调用就打印最终答案，或把工具结果塞进脚本常量，导致改动文件内容后答案不变。多文件任务必须先搜索，再依据搜索输出读取两个文件，最后回答；工具错误要推动下一轮或按明确停止原因结束。

### 核心概念

`AgentLoop` 是状态转移：初始化 user → 请求模型 → 追加 assistant → 串行 dispatch → 追加 tool → 再请求，直到 final/error/limit。事件是观察轨迹，消息是下一轮输入；两者不互相冒充。Rust 的 `async fn`、trait object 与借用在此处就地解释。

### 小节安排

1. **手写三回合状态图**：第一部分单文件样本与本章多文件搜索/读取/回答的输入输出。
2. **实现最小 loop**：按顺序追加 assistant/tool 消息，保留调用 ID。
3. **新增有界搜索并接入受限工作区**：在允许文件清单内搜索关键词，限制文件数、扫描字节和返回数；每回合检查路径、参数和结果。
4. **定义终止状态并打印事件**：区分final_answer、empty_final、model_error和工具失败；从首次循环就设置有限回合兜底，下一章再讲完整预算与重复动作策略。

### 贯穿示例

继续使用预览小站的README与package.json：第一轮search_files查找启动命令，第二轮依据实际命中读取这两份文件，第三轮比较文档与scripts.dev并输出建议。删除配置文件后搜索结果改变，回答应报告依据不足；空结果、坏响应和越界路径有明确结果。离线适配器按实际工具文本构造后续动作，不能预置永远正确的终句。旧ch05_loop的marker文件只作为可选机制对照，不取代贯穿项目或F06验收。

### 实现增量

计划新增LoopState、最小LoopEvent和StopReason，参考现有run_agent_loop_with_adapter而不把新快照视为已实现。调度串行，max_turns从首次运行就有有限值，另沿用01单次超时；07细化预算计数与ActionSkipped。search_files返回路径/命中摘要/截断标记，使用现有范围检查；执行器只读，不能应用候选。

### 验收设计

正常检查三回合顺序、真实tool内容、建议和事件完整；改变scripts.dev后依据与建议必须变化。失败覆盖空final、模型错误、工具错误、无效路径、回放耗尽和持续工具请求触发回合兜底；末尾必有stopped，不panic或伪造工具消息。回归第一部分固定样本；F06 尚未执行。

### 产物与练习

产物是 Rust loop、离线 adapter、事件 JSON、单/多文件 fixture 与 F06 计划快照。练习要求把两个读取调用交换返回顺序，确认消息仍按调用 ID，另删除文件观察搜索输出变化。完成标准是从事件和消息两处证明答案消费了实际工具结果。

### 交接

交给 07 的是可运行多轮 loop、事件序列和停止状态；07 只增加回合、工具、重复动作预算，不改消息语义。08 继续使用同一 loop，在四个时机加入取消和截止。

### 复用与证据

复用 [agent-loop.md](../../docs/chapters/agent-loop.md) 的动态离线 adapter、串行 dispatch 和停止原因，以及 `rust/examples/ch05_loop.rs`、`rust/src/rein/loop.rs`。这些是已有实现与历史离线证据，绑定旧入口；新 F06 同组 fixture、命令和教学验收计划新增，不能用通过代码测试替代。

## 07 让循环适时停止

### 进入条件

读者已有能连续搜索、读取和回答的 Rust loop，理解事件、消息和终止状态。可运行起点是可控回放和两个文件工作区；还没有区分模型回合数、真实工具派发数、重复动作次数，也未定义预算耗尽时下一轮可见内容。

### 问题与失败现象

模型重复读同一文件或返回两个调用，而剩余工具预算只有一个；若只看调用建议数，会超预算或伪造未执行结果。C05 要求预算、重复身份、停止原因分开记录，停止后不再请求模型；CLI 退出 0 只表示报告打印成功，不表示任务成功。

### 核心概念

定义 `max_turns`、`max_tool_calls`、`duplicate_limit` 三个边界；动作身份由工具名和规范化 JSON 参数组成，不包含调用 ID。预算阻止的调用记录 `ActionSkipped`，不生成 tool 输出；`StopReason` 明确 `max_turns/tool_budget/duplicate/model_error/...`。

### 小节安排

1. **分别统计三种数量**：用一次响应两个调用区分返回数和实际派发数。
2. **规范化动作身份**：递归排序对象键，保留数组顺序，解释为何不含 ID。
3. **处理预算不足的同轮调用**：前一项真实执行，后一项跳过并停止。
4. **把停止原因交给调用者**：输出状态、事件、计数和退出语义。

### 贯穿示例

回放一次返回两个 `read_file`，`max_tool_calls=1`：第一项有 `ToolResult`，第二项只有 `ActionSkipped{tool_budget_exhausted}`，不向下一轮伪造结果。两个不同 ID 但同路径的动作在 `duplicate_limit=1` 时第二次跳过。`max_turns=0` 时模型请求数为 0；这些是离线预期，尚未新章执行。

### 实现增量

计划扩展LoopOptions、BudgetCounters、canonical_json、ActionIdentity和ActionSkipped事件。先核对既有请求期限、回合预算，再在dispatch前核对工具预算与重复限制；08加入取消/整次截止后将其置于优先检查点，该扩展不是本章未说明的前置。保留模型原始调用与已执行结果，未执行项不创建tool消息。

### 验收设计

正常检查预算边界的请求和派发计数、重复身份和事件；失败检查零回合、零工具、重复调用、预算不足后不得继续推进。回归第一部分的正常/错误行为、消息 ID 配对，以及拒绝不写与接受后准确写入；特别验证调用 ID 改变不能绕过重复阈值。F07 尚未执行。

### 产物与练习

产物是预算配置、规范化身份、停止事件和 C05 回放/F07 快照。练习把 `max_tool_calls` 从 1 改为 2，对比事件；再只改变调用 ID，确认重复仍被拦截。完成标准是读者能算清模型请求数、返回调用数、实际工具数并解释每个停止原因。

### 交接

交给 08 的是预算检查点、`ActionSkipped` 和停止状态；08 必须在预算之外加入时间/取消竞态，并保留已完成动作。09 读取 S2 全量事件和停止结果，不重新解释预算。

### 复用与证据

复用 [loop-budget.md](../../docs/chapters/loop-budget.md) 的计数边界、`canonical_json` 与示例命令、`rust/examples/ch06_loop.rs` 的现有实现。已有执行记录是历史离线证据，不能证明新章节快照；F07 的 C05 结果和教学验收计划新增。

## 08 取消任务与观察运行过程

### 进入条件

读者已有带回合/工具预算的 Rust loop、事件流和停止原因，理解 `Future` 基础。可运行起点是可控延迟回放与 `ControlSignal` 计划接口；尚未区分请求前取消、等待中取消、返回时迟到结果和工具间隔取消，也没有资源回收说明。

### 问题与失败现象

用户取消后，迟到模型答案仍被采纳，或已经取消的下一项工具继续执行；只打印“cancelled”又无法知道哪些动作已经完成。C05 要求保留真实已完成事件，停止未派发动作，并说明丢弃本地 future 不等于撤回远端请求。

### 核心概念

用可克隆 `ControlSignal`、截止时间和 `tokio::select!` 观察四个竞态点：第一次请求前、模型等待中、模型返回时、两次工具之间。区分 `cancelled/timeout`、已执行结果、未派发跳过和结果未知；事件是运行观察，不是跨进程恢复或安全隔离。

### 小节安排

1. **在请求前检查取消**：确认请求数为 0，说明检查顺序。
2. **在等待中竞争 future 与 signal**：用短取消、长回放制造确定性结果。
3. **在返回时拒绝迟到答案**：保留请求事实但不进入最终答案。
4. **在工具之间停止并回收资源**：观察已完成/未派发，并解释外部副作用限制。
5. **接上CLI取消与实时观察**：将Ctrl-C或明确取消入口映射到ControlSignal；通过逐行事件观察器及时刷新请求、工具与停止事件，不能只在退出后打印汇总。进度输出不泄露密钥或无限打印文件内容。

### 贯穿示例

`cancel-before` 不请求模型；`cancel` 在 20ms 取消、回放 100ms，结果为 `cancelled`；`cancel-at-return` 收到迟到文本但不采纳；`cancel-between-tools` 第一工具结果保留，第二项 `ActionSkipped`。30ms 本地截止覆盖 100ms 模型等待，得到 `timeout`。这些均为离线竞态设计，非服务性能数据。

### 实现增量

计划扩展ControlSignal、Deadline、CancellationPolicy和await_control，使用Arc<AtomicBool>或等价同步原语；复用06的LoopEvent作为唯一运行事件语义，接入CLI信号处理和流式观察器，在loop边界二次检查。future丢弃后的本地资源清理须观察；远端是否停止若无证据则保持未知，不能据此声称已撤销请求。本章不实现写入终止。

### 验收设计

正常检查四个取消时机的请求数、工具数、采纳结果、末尾原因和资源清理。失败覆盖重复取消、截止同时到达、迟到响应、工具观察器取消和 panic；不得采纳停止后的模型结果，不得伪造未执行 tool 消息。回归第一部分固定样本和本部分预算优先级；F08 尚未执行。
