# 第四部分：Agent 扩展——增加可复用能力与协作方式

本部分继承第三部分的 S3：任务有状态、工具受权限和预算约束、候选需批准、结果可验证。目标是计划中的 S4，一个能加载工作方法、接入外部工具并进行受限委派的 Agent。扩展按职责分开讲：16 先组织单 Agent 计划，17 复用方法（可独立于 16），18 定义扩展和 Hooks，19 适配 MCP，20 最后从串行委派进入并行协调。

阅读路线不是全串联：16 依赖 15；17 依赖 11、12、15；18 依赖 05、08、12、15；19 依赖 18 的工具适配边界；20 依赖 07、12、15、16，可不安装 Skill、MCP 或 Hooks。所有分支都复用权限、预算、取消、候选批准、验证和未知结果语义。`F16`–`F20` 与 `S4` 是计划快照，不能用旧索引或章节文件名推断运行时已完成。

本部分检查 C05，并在相应分支具备前置时引用 C06–C07；C08 属于第五部分 IDE 状态，C09 属于第六部分持续演进，不是本部分必要回归。预算、取消和迟到返回持续回归；扩展要证明权限不扩大、验证不绕过；串行委派先证明职责边界，再记录并行冲突、协调成本和人工介入。现有 `docs/chapters/task-planning.md` 主要是架构决策复审材料，应映射到 26–27 的设计分析，不能作为 16 的运行时计划模式证据。

## 16 计划模式：先组织任务，再执行

### 进入条件

读者已完成 15，拥有一次可验证的单 Agent 维护流程，理解状态、预算、批准和停止。已有 `docs/chapters/task-planning.md` 的设计决策登记可作阅读材料，但运行时计划模式尚未实现，不能直接声称已有。

### 问题与失败现象

复杂任务中 Agent 一边猜步骤一边执行，依赖未满足就修改文件；需求变化后旧步骤继续运行，完成条件也被一句“看起来完成”替代。模型输出的 checklist 不能自动成为可执行授权。

### 核心概念

计划是受约束的状态图：步骤有唯一 ID、输入、依赖、完成条件、风险、预算和有效权限；以下 `pending/runnable/running/blocked/succeeded/failed/unknown` 状态名是教学建议，不是现有运行时枚举。执行器只推进依赖满足且当前权限有效的步骤。计划审查、修订、执行切换和任务验收分开，修订后受影响步骤必须回到待审状态；每次实际 apply 仍须经过 14 的具体批准，不要求每个只读步骤人工批准。

### 小节安排

1. **从目标拆成步骤**：用 C01 画读取、候选、审批、应用、验证依赖。
2. **状态与完成条件**：设计 `pending/runnable/running/blocked/succeeded/failed/unknown` 转移。
3. **计划审查与批准**：说明模型建议、程序检查和调用者批准的不同职责。
4. **需求变化与修订**：改变完成条件，找出受影响步骤并撤销过期执行意图。
5. **计划转执行**：定义 `F16` 输入输出和从规划态切换的证据。

### 贯穿示例

预览小站任务先要求修正 README，再要求验证配置。计划列出读取 → 生成候选 → 批准 → 应用 → 验证；若用户改成“只分析不写入”，应用步骤被取消，计划转为只读完成。示例为设计/离线演示，尚不表示已有 runtime planner。

### 实现增量

计划新增Plan、Step、Dependency、CompletionCondition、Revision和PlanState；先画状态转移与依赖，再在本章实现最小串行计划驱动器，复用09运行状态、12权限和15尝试记录。明确planning状态只允许授权的读取/分析，只有切换executing并通过准入才能执行有副作用步骤；计划修订不自动授权。实际apply仍需14的具体批准，完整并发DAG不是本章目标。

### 验收设计

正常：依赖顺序正确，完成条件来自受控检查，计划切换执行后事件可追溯。失败：缺依赖、循环依赖、条件不满足、需求修订、取消和未知结果均阻止错误推进。回归：C05 预算/取消、C06 基线批准、C07 修复停止不被计划层绕过。

### 产物与练习

产物是状态转移图、计划schema、最小串行计划驱动器、两次修订记录和F16计划快照。练习要求先在planning运行只读分析，再切换executing；随后把任务改回只读，观察待派发写入被阻止。完成标准是步骤完成条件可检查、执行切换可观察、旧修订不继续派发，计划状态不能替代验证结论。

### 交接

向 17、20 提供计划状态和步骤依赖接口；17 可把 Skill 作为步骤方法来源，20 可按步骤委派。向 26–27 交接的是设计复审问题，不把本章运行时计划宣称为架构决策记录已实现。

### 复用与证据

复用 `docs/chapters/task-planning.md` 的前提、复审和 `architecture/decisions.json` 检查说明，及 09、12、15 的状态/权限/验证边界。前述文件是已有正文和检查器入口；计划执行器、状态事件和 F16 是计划新增，旧章运行记录不能证明它们已完成。

## 17 Skill：加载可复用的工作方法

### 进入条件

读者已有 11 的来源分层、12 的权限 profile 和 15 的验证/修复流程；能理解方法的输入输出，但不要求 16 的 Plan 结构或运行时实现已经存在。Skill 目录、版本、输入输出和适用范围需要明确。

### 问题与失败现象

把一段长提示词当 Skill 会把隐藏权限和假设带进任务；同名方法版本变化却沿用旧批准，或 Skill 要求的工具超出当前 profile。加载成功也不代表任务结果正确。

### 核心概念

Skill 是带元数据、版本、前置条件、输入输出、工具需求、预算上限和验收方法的可复用工作方法。加载只产生候选方法和约束，core 仍逐次检查工具；Skill 的模型建议、程序检查和任务验收不能互相冒充。版本/摘要绑定计划和快照。

### 小节安排

1. **把方法写成契约**：为 README 维护 Skill 定义输入、输出和停止条件。
2. **发现与选择**：按任务类型和前置条件筛选，说明同名版本冲突。
3. **权限与预算复用**：检查 Skill 工具需求不得扩大当前 profile。
4. **Skill 失败后的有限修复**：沿用 15 的分类和重新批准。
5. **Skill 快照与 `F17`**：记录来源、摘要、实际加载和未验证项。

### 贯穿示例

加载“文档命令维护”Skill，要求 `read_file`、`search_files`、固定验证器；当前任务只读时它不能自动请求 apply。若 Skill 文档含越权 shell 文本，11 的不可信来源和 12 的 profile 仍拒绝。预期记录加载版本、方法步骤和实际工具调用。

### 实现增量

计划新增 `SkillManifest`、`SkillVersion`、`Precondition`、`CapabilityRequest` 和 `SkillSelection`；加载器只读取允许根目录的普通文件并校验摘要。执行仍交给核心 loop，候选/批准/验证复用 13–15。无法确认的 Skill 沙箱能力标为待设计，不声称提示词隔离。

### 验收设计

正常：匹配任务的 Skill 产出可追溯步骤并使用已有权限。失败：缺前置、摘要变化、版本冲突、越权工具、无效 manifest 和预算不足均停止或要求重选。回归：C04 权限拒绝、C05 预算取消、C07 修复分类保持一致。

### 产物与练习

产物是一个带版本的 Skill manifest、选择记录、拒绝记录和 `F17`。练习要求制作只读与维护两个变体，证明同名方法不能跨版本复用批准；完成标准是输入/输出/前置/预算/验收齐全，加载不产生写盘。

### 交接

向 18 交付可声明的步骤方法、工具需求和生命周期钩子位置；向 20 交付“一个 Skill 步骤可委派，但权限与验收仍由 core 控制”的边界。19 只接收工具接口，不依赖 Skill 实现。

### 复用与证据

复用 `docs/chapters/trust-permissions.md`、`docs/chapters/bounded-repair.md` 及 16 的计划契约；旧 `docs/chapters/extension-sdk.md` 只有新版初稿状态，不能视为完成 Skill loader。manifest、加载实现、F17 和真实方法效果是计划新增。

## 18 扩展接口与执行 Hooks

### 进入条件

读者已有 05 的内部消息/工具语义、08 的取消事件、12 的权限检查和 15 的验证；17 的 Skill 是可选输入，不是本章前置。外部扩展边界尚未冻结，不能把 TypeScript 宿主或旧 SDK 当作新版完成证据。

### 问题与失败现象

扩展若直接改 core 状态，会绕过预算和批准；Hook 若能任意改参数，就可能在执行前扩大范围；执行后 Hook 把未知结果改成成功，会破坏恢复和审计。

### 核心概念

扩展接口描述可观察事件和受限请求；Hooks 是执行节点的观察/拒绝/补充记录点，不是隐藏执行器。core 保持状态、预算、权限和验证所有权；扩展只能得到最小事件视图并返回结构化决定。同步、异步、失败和超时都要有明确语义。

### 小节安排

1. **先冻结内部事件**：沿用 RunEvent 和 tool envelope，定义兼容字段。
2. **扩展请求与响应**：区分能力注册、观察、拒绝和建议，不允许扩展自授予权限。
3. **执行前/后 Hooks**：用 apply 前审批和验证后记录展示节点顺序。
4. **超时、取消与异常**：检查 Hook 故障不会吞掉主体调用的未知状态。
5. **扩展快照与 `F18`**：记录注册表、事件序列和回归边界。

### 贯穿示例

注册一个记录候选审查摘要的观察Hook：它能看C06的path、digest和结果类别，不能替换replacement或批准。本轮建议固定失败策略：纯观察Hook超时记录警告，必需的执行前准入Hook失败/超时则阻止派发；执行后Hook失败保留已发生动作与未知状态，不能把结果改写为成功或未执行。限制Hook不得递归触发自身，同样计入期限与调用预算。示例为离线事件演示。

### 实现增量

计划新增版本化 `ExtensionManifest`、`HookContext`、`HookDecision`、能力注册表和生命周期事件接口；沿用 `rust/src/rein/loop.rs` 的 observer 思路，但补上最小权限、错误和取消语义。禁止把 Hook closure 描述为隔离；扩展写外部系统需单独工具和授权。

### 验收设计

正常：合法扩展接收规定事件并留下摘要。失败：重复注册、事件篡改、超时、拒绝、取消、未知结果和不匹配能力声明按契约处理。回归：C05–C07 的预算、取消、批准、验证和修复不受 Hook 绕过。

### 产物与练习

产物是扩展 manifest、生命周期时序图、两种 Hook 记录和 `F18`。练习要求写一个只读观察 Hook 与一个拒绝 Hook，证明二者都不能自行 apply；完成标准是事件顺序可复查、失败不隐藏、权限仍在 core。

### 交接

向 19 提供稳定的工具适配/事件边界；MCP 作为外部工具接入，不应直接操作内部状态。向 20 提供注册扩展的单 Agent 基线，委派任务须携带同样的权限和验证上下文。

### 复用与证据

复用 `rust/src/rein/loop.rs` 的 `ToolObserver`、`ControlSignal` 与 `ExecutorResult`，以及 `docs/chapters/execution-hooks.md`、`docs/chapters/extension-sdk.md` 的主题入口；两篇旧正文标明未完成。版本化接口、Hook 运行时和 F18 是计划新增，入口代码不证明边界完整。

## 19 接入 MCP 工具

### 进入条件

读者已有 18 的扩展注册、事件和错误语义，理解 12 的工具权限与 15 的验证结果；不要求安装或连接真实 MCP 服务。外部协议适配、服务器身份和返回内容信任尚未建立。

### 问题与失败现象

把 MCP 工具列表直接当授权会让服务器扩大工作区范围；远端返回的文本可能是资料、错误或提示注入；连接断开时无法判断副作用，若自动重放会重复动作。

### 核心概念

MCP 是外部工具接口/传输适配层，不替代 core 的权限、预算、批准和验证。先把工具声明映射为内部 typed tool，再按任务 profile 允许具体工具与参数；服务器身份、版本、范围、超时和结果类型进入证据。未知副作用按 15 停机。

### 小节安排

1. **内部工具与外部协议**：解释为什么先统一 05 的消息和结果语义。
2. **发现能力但不自动授权**：对照服务器声明和本地 profile。
3. **参数、范围与返回值**：校验路径、大小、来源和敏感字段。
4. **连接故障与副作用未知**：用写后断连和读超时分别处理。
5. **MCP 快照与 `F19`**：登记服务器摘要、调用 envelope、离线 fixture 和限制。

### 贯穿示例

接入一个只提供 `search_files` 的本地 MCP fixture。服务器声明另有任意 shell 工具，但 profile 只批准搜索；core 拒绝后者。搜索结果指向 README 后仍须通过受控 `read_file` 读取。写后断连另设显式授权的故障 fixture，或复用第三部分已有维护测试；不能在只读 MCP 服务中凭空制造写入。该故障若发生标 `outcome_unknown`，不自动重放。

### 实现增量

计划新增 `McpServerIdentity`、`CapabilityAdvertisement`、`TypedToolAdapter`、`TransportError` 和结果来源字段；18 的注册表保存实际 handler，12 再做 task-level policy。不得把 MCP server 当 sandbox；认证、网络和外部数据保留为环境前提，未实现项显式标注。

### 验收设计

正常：允许的 MCP 工具映射为内部调用并计入预算。失败：未批准工具、参数越界、服务器版本变化、畸形返回、超时、断连和未知副作用分别拒绝或停机。回归：C04 路径、C05 取消/预算、C06 批准基线和 C07 分类不变。

### 产物与练习

产物是服务器能力对照表、适配后的 typed tool 示例、离线 fixture 记录和 `F19`。练习要求禁用一个服务器工具并证明发现列表不会自动获得授权；完成标准是每次外部调用可追踪身份、范围、预算和结果类别。

### 交接

向 20 交付外部工具的统一调用边界；委派者只能分配已允许的工具和范围。向第五部分可交付可展示的连接状态/错误事件，但不能把 MCP 连接成功当产品任务成功。

### 复用与证据

复用 `docs/chapters/mcp-tools.md` 主题入口、18 的扩展边界、12 的权限 profile 和 15 的未知结果语义；现有 MCP 章节标明未完成，不能宣称协议已接通。真实远端互操作、认证和 F19 快照是计划新增，离线 fixture 不代表生产可靠性。

## 20 多智能体与受限委派

### 进入条件

读者已有 16 的计划状态和依赖、08 的停止/预算、12 的权限、15 的验证，以及可选的 17–19 扩展边界。多智能体不是默认前提；先完成单 Agent 串行委派，再讨论并行。

### 问题与失败现象

把任务拆给多个 Agent 后，子 Agent 可能越过范围、重复写入、使用过期基线或互相覆盖；并行速度收益还可能被冲突解决、上下文复制和人工协调成本抵消。父 Agent 不能仅凭子 Agent 的“完成”宣称验收通过。

### 核心概念

委派合同包含目标、输入快照、允许工具/路径、父总预算中的子限额、截止条件、输出 schema、验证责任和取消规则。父 Agent 不能替用户授权，只能收集授权并经 core 的批准门执行；它保留合并、最终验收与未知结果处置，子 Agent 只负责有界子任务。串行先验证交接，再对不相交只读或候选任务做并行；共享写入必须有冲突策略。

### 小节安排

1. **为什么先串行**：把 README 读取、候选生成、验证分给单个子 Agent，核对输入/输出。
2. **委派合同与职责**：定义父/子状态、预算、工具 profile 和完成条件。
3. **串行交接与失败**：子任务失败、取消、未知时父计划如何停或修订。
4. **并行的可分范围**：对不相交文件生成候选，比较冲突、协调和上下文成本。
5. **协作快照与 `F20/S4`**：保存任务图、委派记录、合并审查和评测限制。

### 贯穿示例

串行场景由父Agent委派读取README/package.json并返回证据；父Agent据此生成候选、向用户请求批准，再由core核验授权并执行应用/验证，子Agent没有apply。并行先对不相交文件产生候选；若两份候选写集合重叠、目标摘要过期或依赖的来源变化，合并器标冲突并要求重读、重审，不能仅因它们来自同一个工作区快照就判冲突，也不能自动覆盖其中一份。

### 实现增量

计划新增 `DelegationContract`、`AgentId`、`ChildRun`、`Handoff`、`MergeDecision` 和协调预算。父/子共享事件身份链但不共享隐式批准；子限额来自同一父总账，不能把子限额相加突破父预算；每个子任务复用 12 的 profile、08 的取消、15 的结果分类。并发执行器、冲突合并和跨 Agent 持久化先作为设计/实验产物，不能从现有代码推断已实现。

### 验收设计

正常：串行子任务在范围内完成，父 Agent 能验证输出并继续。失败：越权请求、预算耗尽、取消、迟到结果、过期基线、同文件冲突和子 Agent 伪成功均保留证据并停止/修订。回归：C05–C07 保持；C08 留给第五部分 IDE，C09 留给第六部分持续演进。

### 产物与练习

产物是串行委派合同、两个并行候选、冲突报告、协调成本表和 `F20/S4` 计划快照。练习要求先完成串行再把两个只读子任务并行，记录总预算、等待、人工介入和冲突；完成标准是职责分离、验证独立、未知不重放，不能只看速度。

### 交接

向第五部分交付可在 IDE 展示的任务树、子任务状态、diff/批准/验证事件和冲突提示；产品层不得隐藏父 Agent 的最终验收责任。向第六部分交付一次真实产物链和成本记录，供架构与持续演进实验比较。

### 复用与证据

复用 `docs/chapters/bounded-delegation.md` 主题入口、`rust/src/rein/loop.rs` 的控制/执行语义、12 的权限、15 的修复和 16 的计划边界；旧委派章节仍是新版初稿，不能当运行时实现。串行/并行委派、冲突、协调成本和 F20 验收均为计划新增，实验结论必须绑定固定模型、工具权限、预算和实际记录。
