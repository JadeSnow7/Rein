## 01 用 Python 完成第一次模型调用

正文：[Python 模型调用](../../docs/chapters/python-model-call.md)。

### 进入条件与问题

读者已有任务图，尚无请求程序。目标是获得第一次成功并能解释它，避免先读庞大工程或把 API 失败和代码任务失败混在一起。

### 六节结构

1. 环境准备：Python、虚拟环境、依赖、API 配置与环境变量。
2. 发送请求：让模型回复“你好”并介绍自己；短小完整 SDK 程序。
3. 完整任务：输入可替换的请求程序，生成 C++ Hello World，人工保存、编译并运行。
4. 失败处理：配置、传输/API、响应内容、任务结果四个层次，主动制造可复现错误。
5. 效果检查：正常调用、代码运行、明确失败，并标注真实/离线来源。
6. 任务布置：变化输入、配置故障与缺分号练习。

### 产物与验收

交付最短问候入口、安全请求入口和一个人工验证的 `hello.cpp`。成功要求实际取得回答；代码任务还要求编译与运行通过。离线模式只能证明本地路径。模型自我介绍不能验证部署身份。02 继承这份源码并主动制造错误。

## 02 让 AI 读取代码与日志

正文：[报错与读取工具](../../docs/chapters/python-file-read.md)。

### 进入条件与问题

已有可运行源码与模型调用程序。删掉分号后，模型不知道真实文件或终端报错；从人手传递资料开始解释上下文。

### 小节安排

确定性报错→体验手工粘贴源码与日志→模型请求 `read_file` 与受限 Bash→程序检查并执行→工具结果返回模型→人工检查候选和失败路径。工具往返保留 assistant 请求、执行器检查、tool 结果及后续请求；直接读取模式留作配套实现对照，不作为正文的独立主线。

### 实现与边界

允许读取 `hello.cpp` 与 `compiler.log`；Bash 只接受练习工作区内预先限定的检查命令，不能执行模型提供的任意 shell。环境工具只返回 OS/Python/编译器信息。限定普通 UTF-8 文件、大小和请求次数；工具 ID 正确配对。候选返回完整源码与理由，诊断本身不写目标。

### 产物与验收

同一源码变化应进入新消息；读取失败和越界 Bash 请求明确停止；离线替身明确局限于缺分号样本。读者检查候选并可手工验证，随后把“还需手工对比并粘贴”的问题交给03。

## 03 做一个终端代码修改助手

正文：[终端修改助手](../../docs/chapters/python-suggestions.md)。

### 进入条件与问题

已有诊断与候选；第二章限定了读取权限，模型的候选仍需人工审核。先找到候选修改的位置，再让程序计算差异、等待用户决定，并根据本地执行判断结果。

### 小节安排

准备坏样本并生成日志→人工阅读原文件和候选、定位改动→读者写只读终端 diff 工具→成品入口展示全文和红绿 diff→接受/放弃→源摘要复查与唯一备份→写入→固定编译运行→失败反馈和下一次人工决定→第一部分总作业。

### 实现与边界

差异由程序计算，保留行号与 +/-，无颜色也可读。拒绝/EOF 不写；接受前拒绝过期源码，备份后更新唯一目标。每次候选单独确认。固定命令、临时编译产物、有限等待，不执行模型提供的 shell。编译成功后才运行，检查准确输出与退出码。面向单用户自控目录，不声称通用沙箱或原子事务。

### 产物与验收

坏样本真实编译失败；手写工具能展示原文件与候选的全部差异；拒绝不写；接受后备份和目标字节准确；正常样本编译与运行成功；错误输出和超时不误报成功。总作业允许任意语言实现终端“简易 Cursor”：限定项目文件、自动读取并给出候选和可审查的 diff，第一版可保持只读。保留源码、日志、决定与验证记录，真实模型效果和新手试读独立记录。
