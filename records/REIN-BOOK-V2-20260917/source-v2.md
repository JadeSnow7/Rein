**一、定位与修订目标**

本书面向具备基本编程经验、希望学习 Agent 工程或准备相关岗位的读者。按“不要求读者预先熟悉 Rust”的路线设计，在进入 Rust core 时就地提供必要的迁移知识。

保留 Rust core + TypeScript 宿主与扩展的架构。TypeScript 用于早期快速建立直觉；Rust 接管运行状态、循环、预算和执行边界；TypeScript 后续承担工具宿主、SDK 与领域集成。模型服务商适配接口与 core/宿主扩展协议分别推导。

全书围绕同一个工作区文档维护助手演进：

> 回答文档问题 → 查找相关资料 → 判断内容是否过期 → 提出修订 → 批准与应用 → 执行验证 → 根据失败有限修复 → 按需增加长任务、恢复、扩展与协作能力。

第 00 章交代任务地图、输入与期望产物，说明选择文档维护场景的理由。第 02 章进一步确定任务边界与成功标准。完整实机演示随能力交付补充，尚未实现的终点使用明确标注的任务示意。

原方案八条原则保持不变：

1. 一个章节围绕一个主要问题，提供可观察的学习成果；多个紧密相连的步骤可以构成一个完整闭环。
2. 内容密度过高时拆章；语言、架构或任务对象发生变化时安排有实际产物的过渡。
3. 从当前实现遇到的真实困难推导抽象，每章把新能力接回同一个 Rein。
4. 读者尽早接触成功标准；复杂验证器、权限策略和恢复机制在具体需求出现后展开。
5. 主线自足。阅读材料和附录按需补充，章末提示词也是可选辅助。
6. 区分程序测试、单次任务验收、证据关联与系统评测，分别说明结论的适用范围。
7. 必要边界随能力出现：读取时解释路径约束，运行验证命令时明确执行范围，写入时解释批准和基线，接外部能力时解释对应信任边界。
8. 基础项目以单 Agent 完成；进阶能力由任务需求和比较结果决定是否引入。

“可观察的学习成果”可以是运行能力，也可以是可检查的设计、对照分析或任务规范；不机械要求概念章产生代码变更。

五次阶段汇总的位置和检查项保持原方案：

| 汇总 | 位置 | 核心检查 |
|---|---|---|
| 1：真实资料问答原型 | 04 后 | 文件变化影响答案；错误被保留；适配器复用既有工具 |
| 2：可控混合 Harness | 09 后 | 连续行动、预算、取消、宿主生命周期与未知结果可观察 |
| 3：有依据、可检查的回答 | 13 后 | 上下文策略接回循环；来源、验收规则及证据关联可复查 |
| 4：单 Agent 修改助手 | 17 后 | 补丁、批准、应用、验证和有限修复形成完整流程 |
| 5：可展示与答辩的项目 | 24 后 | 记录评测、失败、代价和取舍，提供复现入口 |

**基础执行策略新增以下显式约定。**

| 事项 | 基础路线决策 | 教学归属 |
|---|---|---|
| 一轮多个工具调用 | 接受多个调用，按确定顺序串行执行，按调用 ID 配对结果 | 06 |
| 单项工具失败 | 返回真实结构化结果；是否继续执行后续调用按明确策略处理 | 06 |
| 预算 | 区分返回的调用数量与实际派发数量 | 07 |
| 取消 | 处理当前调用，停止尚未派发的后续调用；基础路线没有同时运行的兄弟调用 | 08 |
| 宿主并发 | 基础路线最多一个在途工具调用 | 09 |
| 鉴权 | 每次派发前检查对应调用权限 | 14 |
| 多个补丁 | 串行应用，每次检查当前基线；旧基线失效时重新处理 | 16 |
| 流式响应 | 基础路线范围外，使用非流式接口 | 01、06 |
| 重试与幂等 | 默认关闭自动重试；17 推导有限重试策略，19 延伸到持久恢复 | 08、09、17、19 |

未执行调用必须留有事件记录。预算或取消中断一组调用后，不能带着不完整的调用结果关系直接进入下一轮模型请求，也不能伪造工具输出补齐历史。

重试教学区分：

- 已确认未派发；
- 已知失败且允许再次尝试；
- 动作可能发生但结果未知。

只有满足明确条件的前两类才讨论自动重试；重试仍消耗预算并记录尝试身份。基础路线不承诺持久幂等去重或 exactly-once。

**四、正文的组织与学习压力控制**

推荐叙事路径保持：

> 观察任务或失败 → 尝试直接解法 → 解释暴露的限制 → 推导结构 → 分步实现 → 接回 Rein → 验证并讨论取舍。

这是写作检查方式，不要求所有章节复制相同小标题。概念章通过分析或设计成果结束，实现章通过可运行增量结束。

每章写作前确定四项：进入时已经会什么、遇到了什么新问题、本章增加什么、离开时能独立完成什么。过渡章也使用这一标准。

命令和预期输出用于验证教学结论。较长的机器校验脚本放入配套代码，正文解释输入、执行方式、关键结果及失败含义。必要语言知识就地说明，更深入的语言机制链接补充材料。

Rust 知识按使用时机分配：

| 章节 | 主线需要的语言知识 | 延后内容 |
|---|---|---|
| 05 | struct、enum、Result、拥有型数据及必要借用 | 不集中讲复杂生命周期和异步 trait |
| 06 | 循环调用所需的 async/await、借用范围与异步接口 | 运行时取消和资源释放留到 08 |
| 08 | 等待、取消、Future 释放及相关生命周期 | 更深入的类型与运行时细节进入 A.3 |

不在 05 提前要求读者理解 06、08 的复杂接口。

练习包含选择边界、构造反例、补充验收规则或解释另一种设计代价等任务，并给出可检查要求。

固定任务与成功标准从 02 起累积；上下文策略章节使用它们作比较，13 系统解释验证，24 扩大案例与评测。离线夹具、回放与真实模型运行分别标注，不互相替代。

**五、章末“提示词示例”栏目**

栏目主要提供读者发送给 AI 编程或学习助手的参考提示词。Rein 自身的 system prompt、任务消息和工具描述仍在正文按运行时用途讲解。

本版调整为：

- 实现与实验章保留章末栏目。
- 00 可以不设。
- 02 本身已经教授提示词，其正文中的代表性例子可以直接承担该栏目功能，章末只作定位与引用，避免重复。
- 其他确无独立教学价值的概念单元，可以说明省略理由。
- 阶段汇总、阅读材料和附录按需要设置。

栏目重心是**关键句解析**。每章选择两到三个确实影响本章任务的表达，解释它消除了什么歧义、约束了什么行为、对应哪项验收。

“当前基础、目标、范围、协助方式、验收”保留为作者检查清单，不再要求每份提示词机械写成五段。已有代码和上下文可以通过明确引用提供。

各篇重点保持：

| 篇 | 提示词教学重点 |
|---|---|
| 第一篇 | 描述任务，区分请求与执行，提出成功标准 |
| 第二篇 | 保持迁移行为，限定新增能力，表达预算与停止条件 |
| 第三篇 | 指定依据，处理信息缺失，检查来源与验收规则 |
| 第四篇 | 限定修改，展示差异，遵守批准，控制修复 |
