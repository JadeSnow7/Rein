# 00–03 第二轮精修 Spec

来源：用户“开始对 00-03 进行精修”。以当前 book/chapters.json 的新版稳定 slug 为准。承接已完成的第一部分文字审查，本轮精修四篇主线正文，不改历史数字稿和章节验收状态。

## 目标与范围

- 00：用同一维护案例串联角色、能力递进与读者练习，减少项目进度对开篇的打断。
- 01：明确代码阅读路径，解释请求与响应的结构及进程间无对话记忆；不改变已有调用行为。
- 02：让完整提示词可直接复制运行，给出明确的单变量对照及逐项判读方法，补足格式正确但事实错误的具体反例。
- 03：交代七段代码的组装关系，用两次请求和一次本地读取解释消息流，区分协议失败与工具失败，保留全部参数和文件限制。

写作沿用 reports/ch01-author-style.md：完整段落、直接操作标题、概念随操作引入。所有新增命令须给 cwd、前提、预期；正文不混入任务记录编号。不增加运行时能力，不升级依赖。不读取真实密钥或发出真实模型请求。

## 验收基准

修改前保存四篇字节与保护路径哈希，运行 book:check 和从最终 Markdown 提取七段 TS 的既有离线检查。修改后复跑同一基准，执行 hello/config 定向测试、类型检查、站点构建与链接检查；核对 02 完整命令的参数传递与配置负例，无真实网络。主线程审查全部相对本轮基线的差异，核对每章起点、动作、预期与下一章连接。

01 与 03 由 coder 独占修改；主线程负责 00、02、Spec、记录与终审。Rust 对照和汇总页只检查一致性，除非出现本轮引入的冲突，否则保留。旧审查回执仅支持旧字节，新稿以本轮回执为准。

成功仅指四章文字精修和离线验证；真实服务、初学者跟做与快照验收仍未完成。未授权 commit、push 或 deploy。
