# Rein 设计决策与连续演化工具首批增量

版本：EVOLUTION-SLICE-1。来源：用户先询问 AI 架构设计与长期维护不足如何解决，随后确认“好的请开始补充”。本轮把已讨论的两项优先能力落为可运行工具、教学补充和实验方案。

## 范围与现状

当前工作区 HEAD 为 `1dfa82b9d90196c2294f61914d2017449e5548e3`，包含大量已存在的未提交工作。根 Cargo workspace 的 `core/`、`runtime/` 是新的产品增量；`rust/`、`ts/` 保留教学实现。现有运行时使用离线模型和只读工具。本轮保持这些代码、接口和历史证据字节不变。

交付两套使用 Node 内置库的独立本地工具，以及第 18、24 章的对应增量。它们是开发与评测工具，不能写入 Rein runtime 的任务状态，也不构成 R1/P0 或完整章节验收。不开启付费模型实验、不改外部 Veriflow skill、不提交/推送/发布。

## SC-DECISION：设计决策及失效检查

- 权威登记表：`architecture/decisions.json`，保留明确的决定、理由、适用范围、替代方案、前提、复审条件和来源；人工采纳状态与机器检查结果分开。
- `scripts/architecture/decisions.mjs` 提供只读 CLI 和可测试模块。CLI 使用 `--root <repo> --registry <json>`，输出 JSON；0 表示全部已采纳决定的已声明前提仍匹配，1 表示需要复审/无法确认，2 表示输入或运行错误。
- 前提以仓库内文件路径及 SHA-256 绑定。匹配为 `applicable`；已读文件发生变化为 `review_required`；缺失、无法读取或没有足够前提为 `undetermined`。`applicable` 仅表示声明的前提匹配，不证明架构正确。混合结果须保留逐前提原因，未知不能成为通过。
- proposed/superseded 等人工生命周期不能被检查器自动提升为 accepted，历史记录不可自动刷新 hash。复审必须由维护者生成新版本并保留旧结论。
- 拒绝畸形登记、重复 ID、非法摘要和越界路径；拒绝前提路径经过符号链接，避免把外部内容当作仓库事实。登记内容本身不作为可执行指令。
- 真实登记示例绑定当前根 Cargo workspace 与 core 边界，并明确复审条件；不能重述全部 DECISIONS.md 为第二权威，须引用具体决定。

## SC-EVOLUTION：连续演化执行与评分

- `scripts/evolution/` 提供独立 runner、可运行离线 demo、测试与 README；`fixtures/evolution/` 提供冻结的种子项目、12 轮连续维护任务及可信适配器/验证器。
- 首批使用单文档种子 `seedFile`，不宣称支持任意多文件项目迁移。每条轨迹从种子初始化一次；下一轮必须继承前一轮真实产物，并保留各轮快照。适配器和验证器在独立调用中运行，禁止把适配器声称成功当作验证通过。
- 计划声明序列身份、每轮任务、验证项及明确的退役/替代规则。旧要求仍有效时持续回归；旧检查只有明确的需求替代理由才能退出，不能每轮悄悄丢弃。
- 按轮记录输入/输出内容指纹、原始进程结果、活动检查结果、功能通过情况、新增回归、累计回归事件、修改文件数、实际墙钟时间；未知 token/cost/人工时间为 null。失败或未确定保持真实状态。
- CLI/模块的具体参数由实现者在本目录 README 冻结，采用显式路径、参数数组和无 shell 子进程；输入验证在执行前完成。输出目录必须全新且与种子/工具/项目输入不重叠；不得覆写已有证据。进程设置有限超时。
- 离线 demo 用已知正确适配器和故意引入历史回归的适配器校准评分器；至少证明一次“当前新增要求通过，但旧要求失败”。两组都是确定性 fixture，不是 AI 对照实验，不报告架构能力提升或性能优势。
- demo 的 12 轮要求可以公开；不得声称同一用户的普通子进程构成盲测或安全沙箱。真实模型、未来任务隔离、等预算三组比较和多序列复验写成后续实验方案。

## 基准与验收

先写测试并在源码缺失时运行，保存实现前结果。主线程核对后才开始产品代码。实现后复跑同一测试并执行实际 CLI。

| 指标 | 输入与预期 | 方法 |
| --- | --- | --- |
| MET-001 | 当前摘要匹配通过；变更需复审；缺失/空前提未知；畸形/重复/越界/符号链接拒绝；不改登记表 | Node 测试与当前仓库只读 CLI |
| MET-002 | 后轮继承前轮输出；持续旧检查；显式替代；故意回归被检测；进程失败/超时不通过；非法输入在调用前拒绝；全新输出不覆写；缺失成本为 null | runner 测试与 12 轮离线正负校准 |
| MET-003 | 两章命令可执行；文档与 CLI/实际结果一致；构建和目录检查通过；原有产品/教学源码、合同、索引与快照保持字节不变；其他任务并行修改的文档单独列示 | 最终正文命令走查、book:check、build、基线 hash 比较 |

本轮验收限于上述工具和文档。连续演化评分基础设施通过，不等于 AI 长期维护能力得到提高；真实三组实验尚未运行。整库未提交改动不在本轮整体审查范围。

## 验证方法修订

实施前审阅发现演化基准初稿存在 `.mjs` 中使用 `require`、同步验证函数使用异步异常断言、首次失败冒充历史回归等缺陷，已要求先修正；后续 Node `-e` 参数及重叠路径用例也按真实入口纠正，保留原基准回执。明确首批是单文档纵切。运行时发现同工作区其他任务正在修改第一篇文档，MET-003 因此明确源码保护与并行文档观测的不同范围；未放宽任一工具行为、回归检查或产品源码保护要求。
