# HelloWorld——从模型调用开始

在ChatGPT中，你输入 hello，按下发送，一句问候就回来了。你有没有想过，按下发送之后，到回答出现之前，那句话去了哪里？

你想想看，平时我们关心的是回答好不好，很少需要知道请求的地址，更不用自己检查返回的 JSON。输入框替我们省了不少事。

这一章，我们把输入框换成终端。

就说一句 hello。

<span id="from-reading-0"></span>

我觉得，第一次调用能把这么一件小事做完整，就已经很有价值了。你会亲手准备配置，用 OpenAI 的 TypeScript SDK 发出一条消息，再检查回答。运行不顺利时，我们就沿着它走过的路，把错误处理一点点补上。

本篇是 TypeScript 版，[Rust 版](./01-rust.md)做同一件事。先选一种你熟悉的语言，不需要两套环境一起装。

本章只处理非流式 Chat Completions，一次运行发一条 `user` 消息，默认内容是 `hello`。成功时打印非空回答，退出码为 `0`；失败则退出 `1`。回答不必和书上一字不差，你读一下，确认它确实在回应问候即可。

1、把仓库和环境准备好

先确认电脑上有 Git 和 Node.js 22 或更高版本。没有的话，分别从 [Git 安装页](https://git-scm.com/downloads)和 [Node.js 下载页](https://nodejs.org/en/download)安装。Node.js 通常会一起安装 npm，装好后重新打开终端。

```bash
git --version
node --version
npm --version
```

看到三个版本号，再在准备存放项目的目录里执行。已经有本章工作副本的读者，直接进入那个目录即可。

```bash
git clone https://github.com/JadeSnow7/Rein.git
cd Rein
```

现在站在仓库根目录，也就是同时看得到 `docs/`、`ts/` 和 `package.json` 的地方。

这里有个版本细节。本次 SDK 教程配套 `ch01-helloworld`，旧的 `ch01` 仍保存手写 HTTP 客户端。新版标签目前随本地交付提供，尚未推送到远程时，新克隆仓库无法获取它。预览本次交付请使用这份本地仓库；远程发布后，才可以在新克隆仓库中使用下面的获取命令。

```bash
git fetch --tags
git switch --detach ch01-helloworld
npm ci
```

`git switch` 切换的是整个仓库的代码版本。已经改过文件，就先保存自己的工作。准备在快照上做练习，可以用 `git switch -c my-ch01` 建自己的分支。

`npm ci` 按锁文件安装依赖，包括本章使用的 `openai` SDK。说真的，第一次装依赖也可能遇到网络问题，但这时还没有请求模型。先解决终端里的安装错误，再继续运行。

2、准备 API key，顺便把另外两个值找齐

很多朋友可能不知道，网页聊天账号和 API 调用凭据要分别准备。API key 是给程序使用的凭据，服务商用它确认请求来自哪个账户。

想从成本较低的选择开始，可以打开 [DeepSeek 官方平台](https://platform.deepseek.com/)注册或登录，在控制台创建自己的 key，查看账户余额，再打开[模型与价格页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)比较可用模型的输入和输出单价。先按本章的少量调用需要准备余额即可。

这里不写一个永久有效的价格。官方会调整模型与计费，读到这一章时，控制台和价格页才是你要核对的地方。你如果已有其他 OpenAI 兼容服务，也可以继续用。

回到这次 hello，我们要找齐三个值。API key 是凭据，base URL 是请求发往的地址，model 是服务商识别模型的名字。三者来自同一家服务，别把一家的 key 配上另一家的地址。

截至 2026-09-13 查阅的 [DeepSeek 首次调用说明](https://api-docs.deepseek.com/zh-cn/)，OpenAI 格式的根地址为 `https://api.deepseek.com`，示例模型为 `deepseek-flash`。填写时仍请核对当时可用的模型名。

从仓库根目录进入 `ts/`，首次配置时复制模板。已有 `.env` 就直接编辑，别覆盖原文件。

```bash
cd ts
cp .env.example .env
```

Windows CMD 用 `copy .env.example .env`。在编辑器里打开 `.env`，填写三项。

```dotenv
REIN_BASE_URL=https://api.deepseek.com
REIN_API_KEY=替换为自己在控制台创建的密钥
REIN_MODEL=deepseek-flash
```

SDK 会在根地址后请求 `/chat/completions`，所以别再把完整接口路径填进 `REIN_BASE_URL`。模板里的 `REIN_ALT_*` 留给后续章节，本章不读取。

这块需要注意一下，`.env` 已经被 Git 忽略。把 key 留在本机配置里即可，源码和练习答案都用不到它。

3、发出第一声 hello

仍在 `ts/` 目录，执行这一条。

```bash
node --import tsx --env-file=.env src/hello.ts hello
```

`tsx` 负责运行 TypeScript，`--env-file=.env` 明确加载配置，末尾的 `hello` 就是我们要交给模型的话。不写最后一个参数，程序也会默认使用 hello。

这条命令会请求配置的服务，并产生相应 API 用量。成功时，终端可能出现这样一句话，下面只是示意，并非本次执行的真实结果。

```text
Hello! How can I help you today?
```

在 macOS / Linux shell 中，紧接着执行 `echo $?` 查看上一条命令的退出码；PowerShell 查看 `$LASTEXITCODE`，CMD 查看 `%ERRORLEVEL%`。成功应为 `0`。

收到问候了？先停一下。

我们已经让终端从网络另一头拿回了一段文字。回答可以是英文，也可以是中文，程序没有拿一句固定回复去和它比较。非空是程序的最低检查，读一下是否回应了问候，是你的检查。

如果还没收到，继续往下读。先别把所有问题都归到模型身上。

<span id="解析-http-成功之后还要检查什么"></span>

4、SDK 到底帮我们做了什么

SDK 可以理解为一组已经写好的调用方法。本章安装的是 OpenAI 官方维护的 `openai` 包，来源可以在 [SDK 说明](https://developers.openai.com/api/docs/libraries)中核对；项目锁定版本，由 `npm ci` 复现安装。

打开 `ts/src/hello.ts`，其中真正发起调用的核心很短。下面摘出 SDK 这一段，`config` 来自本章的配置读取，`prompt` 来自命令行；它是解释用片段，完整入口已经在刚才运行的文件中。

```ts
const client = new OpenAI({
  apiKey: config.apiKey,
  baseURL: config.baseUrl,
  maxRetries: 0,
  timeout: 30_000,
})

const response = await client.chat.completions.create({
  model: config.model,
  messages: [{ role: 'user', content: prompt }],
  stream: false,
})
```

`new OpenAI` 建立客户端，告诉它地址和凭据。`model` 选择模型，`messages` 放消息，`role: 'user'` 表示这句话来自用户。`await` 等待请求返回，`stream: false` 表示这次拿完整响应。

其实吧，光看方法名容易觉得它像一个本地函数。可消息走的是网络。

```text
命令行 hello → SDK 组织 JSON → POST /chat/completions
             → 服务返回响应 → 读取 choices[0].message.content
             → 打印回答
```

`choices` 是候选列表，本章读取第一个候选里的消息文本。SDK 帮我们组织请求和解释 JSON，但兼容服务不一定每次都返回预期字段，所以入口还会检查回答。

`maxRetries: 0` 关闭默认重试。完整源码还传入一个由计时器控制的 `AbortSignal`，把响应体读取也纳入整体 30 秒的等待期限；上面的核心片段省略了这段等待控制。SDK 自带的 timeout 和整个调用完成的期限不能混为一谈。

怎么说呢，我们这次想看清一次交换，遇到失败就先停下来，读完线索再决定下一次动作。

<span id="failures"></span>

5、从请求走过的路，逐步补上错误处理

只有一屏报错的时候，挺容易让人犯嘀咕，代码是不是全错了？？？

我觉得先问一个小问题更有用，最后确认完成的是哪一步？

第一层，还没上网，配置就可能有问题。在 `config.ts` 中，程序读取三项环境变量，空值会抛出 `ConfigError`。地址还会经过 URL 解析与协议检查。到 `hello-safe.ts` 的入口，我们给它一个专门的出口。

```ts
if (error instanceof Error && error.name === 'ConfigError') {
  console.error(`失败（config）：${error.message}`)
  return 1
}
```

这段位于 `main()` 的 `catch` 内。它让缺少变量或地址格式错误停在本地，也告诉你该改哪项配置。至于 `Cannot find package 'openai'` 这样的错误，连 SDK 导入都没完成，需要回仓库根目录检查 `npm ci`；程序自己的 `catch` 不能修复尚未加载成功的依赖。

第二层，配置通过了，连接仍然可能失败。DNS 解析、代理、TLS 或传输中断都可能让 SDK 抛出连接异常。我们在 `classifyOpenAIError()` 中判断 SDK 的错误类型，而不是从一段英文报错里猜原因。理解这一层，可以先看下面的分支示意。

```ts
if (error instanceof APIConnectionTimeoutError) {
  return new SafeCallError('timeout', '等待超过期限，请检查网络和服务状态。')
}
if (error instanceof APIConnectionError) {
  return new SafeCallError('network', '连接或传输失败，请检查地址、代理和网络。')
}
```

这是按 SDK 类型分支的核心示意，完整实现还处理本地等待期限触发的取消。超时要比一般连接错误先检查，因为两种类型可能存在继承关系。

超时并不能证明服务端没处理。也许请求已经到达，只是回答还没读完。这个边界我也没法替你的网络猜出来，先查看服务商的请求记录和状态，再决定是否重发。

第三层，收到 HTTP 响应，服务却拒绝了请求。顺着上面的思路再往前走，`401` 常与凭据有关，`403` 要检查权限，`404` 则要核对根路径和模型名。

在 `classifyOpenAIError()` 的 HTTP 分支中，读取 `status` 和服务返回的 `code` 后，逐个处理这些情况。以 429 为例，下面是两条判断的简化示意。

```ts
if (status === 429 && code === 'insufficient_quota') {
  return new SafeCallError('quota', '检查服务商账户额度或余额。')
}
if (status === 429 && code === 'rate_limit_exceeded') {
  return new SafeCallError('rate-limit', '降低请求频率，稍后再试。')
}
```

你看，同一个 429，后续动作并不一样。完整实现识别更多常见 code，遇到不认识的值，就提示继续核对原因，不擅自把它认成限流。5xx 则单独提示服务端失败。程序保留排查方向，不会自动再发一遍。

第四层，HTTP 成功，也要检查回答。这段检查位于 `readHelloText()` 的末尾，前面的分支已经确认 `choices` 是数组、第一个候选及 `message` 都是对象。

```ts
const text = (message as { content?: unknown }).content
if (typeof text !== 'string' || text.trim().length === 0) {
  throw new SafeCallError('response', '模型响应缺少非空的 choices[0].message.content。')
}
return text
```

缺字段、坏 JSON、空白回答，都不能因为状态码是 200 就算完成。其实我们做的判断很朴素，拿到的东西要能继续用。

几层判断合在一起，就是 `ts/src/hello-safe.ts`。它负责把预期失败变成短诊断，入口统一返回退出码 `1`。想看完整文件，可以展开下面的源码，对照刚才几段判断的位置。

6、把这一次的结果记下来

有成功回答，就记下调用时间、配置中的模型 ID、输入 hello、回答摘要和退出码。当前 CLI 只输出回答，没有显示服务端回报的实际模型 ID，所以不要把配置的名字写成已核对的服务端元信息。

暂时没有可用 key，也可以先检查本地代码。这里从 `ts/` 回到仓库根目录，再执行测试。

```bash
cd ..
npm run typecheck
npm test
npm exec --workspace ts -- vitest run tests/hello.test.ts --reporter verbose
```

本地测试提供受控响应，检查请求形状和失败处理。它们不读取 `.env`，也不请求真实模型。真实连通性这项，没做就记「未验证」。

说实话，这种记录看起来有点笨，但过一段时间再打开项目，你会知道自己那时到底验证了什么。
