# 11 获取外部资料：按需读取与检索

**状态：新版教学初稿，运行集成与逐章验收待完成｜永久免费 · Apache-2.0**

10处理的是已经进入对话的历史。现在的问题是：工作区有许多文件，我们该把哪几份资料放进去？读取全部内容容易超过预算；只读取文件名看起来相关的资料又可能漏掉真正的依据。

## 先检索，再读取

把用户问题转成搜索条件，在允许的工作区内查找候选文件。搜索结果只是位置线索，不能直接当成文件全文。模型随后请求read_file，core核对结果身份和来源版本后才将正文送入后续上下文。

检索器应保留搜索范围、查询、命中路径、排序和截断信息。空结果只说明当前范围与当前查询没有找到内容，不证明项目中不存在这个事实。可以扩大查询或返回依据不足，但不能凭常识填补。

## 用变化区分真实读取与固定答案

既有四策略实验提供on-demand和retrieval入口，作为本章对照材料：

```bash
node scripts/ch08-compare.mjs --strategy on-demand
node scripts/ch08-compare.mjs --strategy retrieval
```

这些命令运行保留的独立实验，不能替代新版loop接入验收。观察选中文档、来源、工具记录和信息不足结果；把资料副本中的事实改掉，再检查回答是否变化。不要修改expectedFacts来迎合新答案。

新版主线需要让搜索与读取结果实际进入同一个loop。验收时检查工具消息中只有真实读取的内容，未读文件不能出现在引用里；删去唯一依据时不能继续报告已找到答案。

## 提示词示例

```text
请围绕当前问题检索工作区资料，再读取命中文件。
保留查询范围、命中与实际读取来源；空结果不等于事实不存在。
删去唯一依据后，应明确报告信息不足。
```

“再读取”区分命中线索与证据；“范围”限制结论适用性；“删去唯一依据”检查是否会补造事实。**试用状态：未试用。** 使用前请阅读[《提示词示例使用说明》](../prompt-examples.md)。
