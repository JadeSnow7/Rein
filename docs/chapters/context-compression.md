# 12 将资料压缩接入循环

**状态：新版教学初稿，运行集成与逐章验收待完成｜永久免费 · Apache-2.0**

检索缩小了资料范围，但选中的正文仍可能超过发送预算。我们希望减少发送内容，同时能说明每句话来自哪里，以及删去了什么。

## 先选择可复现的压缩方式

本章采用抽取式压缩：按固定顺序挑选与问题相关的原文片段，而不是让模型改写摘要。片段保存源路径、源文件SHA-256、起止位置与原文；压缩前后使用同一种估算单位计量。它便于定位信息损失，但不能保证提取到了所有必要事实。

压缩外部资料与裁剪对话历史是两项操作。10中的调用与结果配对不能被压缩器破坏；本章的输入是来源文件片段，输出是带来源的资料视图。完整资料与完整运行历史仍供审查使用。

## 接回实际循环

先读取并绑定来源版本，再从资料构造压缩视图，检查必要依据和预算，最后交给模型适配器。仅在报告里打印压缩结果，不算完成集成。至少构造三个输入：原文超预算但保留片段可进入循环；全部必要片段仍放不下；资料根本没有回答所需事实。

前一种检查模型确实收到压缩内容及引用标记；后两种停止或返回明确的信息不足，不制造答案。预算收益按实际发送单位报告，不能转成未经服务计量的token节省或费用收益。

## 保留独立实验

四策略实验继续使用原数据和独立入口：


这些检查对实验自身有效；新的压缩loop仍须单独验证。练习：把一个关键结论放在资料尾部，检查固定窗口是否丢失它，再比较抽取选择的代价。

## 提示词示例

```text

必要依据不足或仍超预算时停止，不补造结论。
```
