# 02 写一份合格的提示词

**状态：待撰写｜永久免费**

我们在上一章已经提到过，大模型的本质是无状态随机函数，其输出由输入决定，当我们使用大模型时，提高输入质量最简单的方式就是提示词约束，而提示词工程，也正是 Agent 开发，或者说是 Harness 中极其重要的一环。

1、拒绝许愿式编程

很多最初接触大模型的人往往会将大模型当做许愿机，不断地发送请求——接受更改——粘贴报错——接受修改。这样虽然能快速解决部分报错，却往往会带来更多的错误，直至整个项目无法持续维护下去。

由于大模型的随机性，我们如果不加以约束，只是一味许愿，最终必然导致崩溃。

2、提示词优化

许愿式编程最大的问题在于我们很难一次性清晰地描述自己的需求，例如

```text
斐波那契数列
```

如果你想大模型多次发送上面这段话，会得到很多大相径庭的结果，可能的回答包括斐波那契数列的定义、斐波那契数列的简介、用 Python 计算斐波那契数列，出现这种现象正是因为大模型并不清楚你发送这句话时的需求，因此只能根据概率预测，随机生成一个回复。

因此，更好的版本是：

```text
用 c++ 写一个计算斐波那契数列的程序，要求使用递归函数
```

这样大模型就能更好地生成你需要的回复。
