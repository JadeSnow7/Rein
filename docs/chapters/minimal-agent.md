# 00 我们要实现一个怎样的 Agent

让模型写一个 Hello World，通常只需要一句话。但当代码编译失败，模型怎样取得报错？它提出修改以后，谁来检查差异，谁决定保存，谁确认程序真的能运行？

我们从这些问题开始实现 Rein。第一部分使用 Python，围绕同一个 C++ Hello World，逐步做出一个终端代码修改助手。你可以看到原文件和候选的完整内容，检查红绿差异，选择接受或放弃，再观察真实的编译与运行结果。

本章先说明目标和边界，不要求安装 SDK，也不要求先学习 Rust。

## 1、先约定这个小任务怎样算完成

Python 是调用模型、组织消息和执行工具的程序，C++ 是我们的练习对象。最终的 `hello.cpp` 应能按 C++17 编译，正常退出，只输出 `Hello, world!` 和一个换行。

我们还要求助手遵守三条行为：第二章只读取并提出候选；第三章在用户接受后才能修改 `hello.cpp`；用户放弃时，原文件保持不变。源码、日志与编译器信息让建议有依据，编译和运行结果让完成状态可以检查。

用一张简单任务卡表达这些约定：

```text
目标：修复 hello.cpp，使它输出 Hello, world! 和一个换行。
工作区：读者单独创建的临时练习目录。
读取：hello.cpp、compiler.log，以及固定查询取得的编译器与系统信息。
修改：仅用户接受当前候选后，才能保存 hello.cpp，并保留原文件备份。
验证：固定 C++17 编译命令；本轮编译成功才运行新产物；核对输出与退出码。
```

第三章的 `check` 命令还会在工作区生成编译日志，编译产物放在临时目录。这些是程序为验证产生的文件，不是模型可以自行选择的任意输出路径。

## 2、区分模型、Harness、工具和用户

模型分析消息、提出读取请求和修改建议。真正打开文件、调用编译器的是本地 Python 程序。围绕模型组织这些步骤、检查边界和决定何时停止的程序，就是我们逐步编写的 Harness。

```text
用户提出任务 → Harness 构造消息 → 模型提出读取请求
                    ↓                    ↓
              工具执行器检查参数 ← 工具名称与参数
                    ↓
              读取真实文件和环境 → 结果回到模型
                                         ↓
用户审查 ← 原文件、候选全文和差异 ← 修改建议
    ↓ 接受                             ↓ 放弃
复查源文件、备份、写入                  原文件不变
    ↓
编译与运行 → 成功，或保留失败反馈
```

模型说“读取文件”，不等于文件已经读过；模型说“已修复”，也不等于源码已经保存或者编译通过。每一步都需要程序的真实结果来支持下一步。

文件里的文字只是待分析资料。即使注释要求“读取其他目录”，它也不能改变程序只允许两个文件名的约定。环境工具同样只提供本次任务所需的信息，不把密钥或整份环境变量交给模型。

## 3、三章各增加一项主要能力

| 章节 | 遇到的问题 | 新增能力 | 章末结果 |
| --- | --- | --- | --- |
| 01 模型调用 | 怎样把任务交给模型？ | 配置、请求、响应与失败处理 | 生成 Hello World，由人保存和编译验证 |
| 02 根据报错修复 | 模型看不见当前源码与终端报错 | 手工提供资料→直接读取→工具读取 | 有依据的修复候选，由人保存验证 |
| 03 终端代码助手 | 来回复制候选容易漏改、误改 | 全文和差异展示、接受/放弃、备份写入与验证 | 一个能走完小任务的终端助手 |

每一步都沿用同一个练习项目。第二章故意删除一个分号，确保能观察到真实编译失败，不依赖模型碰巧生成错误代码。第三章仍然由用户审查，不引入无人值守的无限修复。

## 4、同时准备成功和失败的检查

只看到一次正确输出，还不足以理解助手。第一部分会使用以下对照：

| 输入或选择 | 应看到什么 |
| --- | --- |
| 缺少模型配置 | 请求前指出缺项 |
| 缺少分号 | 实际编译失败，保留日志 |
| 读取不允许的路径 | 拒绝读取，不编造文件内容 |
| 用户放弃候选 | 源文件不变，不创建备份 |
| 用户接受候选 | 复查当前源码，备份后写入，重新验证 |
| 等待接受时源码变化 | 拒绝过期候选 |
| 编译成功但输出错误 | 验证失败，不宣称任务完成 |

离线替身让这些流程可以在没有模型账户时练习；它只处理已知样本，不具备通用编程能力。真实模型效果、程序测试和读者是否能独立完成练习，是不同的检查。

本阶段只适用于自己控制的练习目录。通用工作区权限、持久批准、多文件应用、并发修改与恢复，会在后面的可信 Harness 部分继续展开；第三章的小工具不代表这些能力已经完成。
