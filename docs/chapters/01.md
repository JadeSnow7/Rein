# HelloWorld——从模型调用开始

在ChatGPT中，输入 hello，按下发送，等一会儿，一句问候就出现在屏幕上。你可以回想一下，按下发送到文字出现之间，发生了什么？

那个输入框替我们藏起了不少事情。消息发到哪里，谁来证明你有调用资格，要用哪个模型，等不到回答又怎么办。平时用 ChatGPT，这些细节很少需要你操心。

现在，我们把输入框换成终端，自己把这一次交换接起来。

就说一句 hello。

<span id="from-reading-0"></span>

本章的任务很具体，使用命令行，通过 SDK 向一个支持 OpenAI 兼容 Chat Completions 接口的服务发送一条 `user` 消息，内容是 `hello`，取得一段非空文本，并检查程序是否正常退出。读完之后，你还要能解释一次失败卡在了哪里。

我觉得，第一章把这件小事做完整就够了。模型的回答不需要惊艳，也不需要跟书里一字不差。你可以从 [TypeScript 版](./01-ts.md#first-run)或 [Rust 版](./01-rust.md#first-run)开始，两版完成同一件事，选择你更熟悉的语言即可。

<span id="first-run"></span>
<span id="确认环境-先完成一次离线检查"></span>

1、把环境准备好，再切到本章源码

两版都从拉取 Rein 仓库开始。TS 读者检查 Git、Node.js 和 npm，Rust 读者检查 Git、Rust 与 Cargo。具体安装、版本和执行目录写在各自正文里，复制命令时别省掉 `cd`。

这里有个很容易忽略的小坑。`git switch --detach ch01-helloworld` 会把整个仓库切到本章快照。它不会运行程序，也不会切换网页语言。已经写了自己的代码，就先保存工作；想继续修改快照，可以再用 `git switch -c my-ch01` 建立自己的练习分支。

旧标签 `ch01` 保存的是手写 HTTP 客户端版本。新版 SDK 教程使用 `ch01-helloworld`，两者不要混用。新版快照在本地交付，远程尚未发布时，新克隆的仓库取不到它；此时需使用这次交付的本地仓库，发布后再按正文从远程获取。

遇到终端、Git 或异步语法不熟悉的地方，再打开[阅读 0](../readings/00.md)。它是一份随手查的补充材料。

<span id="live-call"></span>

2、拿到调用所需的三项配置

API key、服务地址、模型名，要一起确认。key 是谁发给你的，请求就发到谁的服务，模型名也要从同一家的文档中选择。

想控制第一次练习的成本，可以从 [DeepSeek 官方平台](https://platform.deepseek.com/)了解 API 服务。在自己的账户里创建 key，查看余额，再对照[首次调用说明](https://api-docs.deepseek.com/zh-cn/)填写地址和模型名。准备充值前，读一下[官方价格页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)，确认输入、输出的计费方式，按实际需要投入即可。价格与可用模型会调整，两版正文都保留了官方入口。

你如果已经有别家的兼容服务，也可以继续用。这里练习的是同一条调用路径。

<span id="request-response"></span>

3、用最短的 SDK 示例发出 hello

两版都会先给出一份能直接运行的小程序。TS 使用 OpenAI 的 JavaScript / TypeScript SDK，Rust 使用社区维护的 `async-openai`。它们把配置和消息组织为 HTTP 请求，处理返回的数据，省去我们手写一整套收发代码的工作。SDK 的来源与用法可查 [OpenAI SDK 说明](https://developers.openai.com/api/docs/libraries)和 [async-openai 文档](https://docs.rs/async-openai/)。

```text
终端里的 hello
  → SDK 组织请求
  → 网络连接与 HTTP 交换
  → 服务检查身份、模型与请求
  → SDK 读取响应
  → 程序取出回答并打印
```

这是一条理解 API 调用的简图。ChatGPT 产品内部还有自己的服务逻辑，我们并没有复现它。

运行之后，先看有没有非空回答，再看退出码。成功为 `0`，失败为非 `0`。非空文本让程序通过本章的最低检查，你还要亲自读一下，它是不是在回应这句问候。HTTP 成功、字段有效与回答有意义，是需要依次确认的事情。

<span id="failures"></span>

4、没收到回答，就沿着请求走过的路找

怎么说呢，第一次卡住挺正常。安装 SDK 失败、地址拼错、key 失效，在终端里都可能变成一屏报错，但处理办法完全不同。

两版正文会在最简程序上逐步补上错误处理。先检查本地配置，再看连接和超时，随后处理服务返回的拒绝信息，收到成功响应后继续检查回答字段。每加一段代码，都解释它帮我们多看清了哪一步。

看到 `401`，检查身份凭据；看到 `403`，检查权限。`404` 还需要核对地址路径和模型名。至于 `429`，别急着一直重发，先看服务返回的是速率限制，还是额度、余额或用量上限。SDK 的错误类型名字不一定说得完全部原因。

如果超时，只能确认程序没有在等待期限内取得可用结果。服务端可能已经处理了请求。本章关闭 SDK 自动重试，把结果交还给你，再决定下一次动作。

<span id="verification"></span>
<span id="先使用已有样本"></span>

5、给第一次调用留下记录

记录调用时间、所用模型、输入 `hello`、回答摘要和退出码。key 不在记录里。

还没有可用 API 时，可以运行两版各自的本地测试，学习错误是怎样被识别的。不过，真实调用这一项仍然写「未验证」。本地测试不能替远程服务回答，它只能帮助我们检查客户端的处理方式。

6、课后再动手改一点

<span id="exercise-01"></span>
<span id="练习一-把阅读-0-的规则迁移到新结构"></span>

<span id="exercise-02"></span>
<span id="练习二-在发送之前制造错误"></span>

练习 02，在独立练习配置中留空一个必填项，运行带错误处理的入口，找出错误类别和退出码。解释为什么这一步不需要请求远程服务。

<span id="exercise-03"></span>
<span id="练习三-读懂历史录制的两层结构"></span>

练习 03，运行本地失败用例，对照网络故障、HTTP 拒绝和空回答。每个结果写一句下一步检查方向。具体命令和需要观察的字段见对应语言版。

<span id="exercise-04"></span>
<span id="练习四-完成一次真实调用-并记录证据"></span>

练习 04，整理自己的一次真实调用记录，或者明确注明未验证。再补一句话，本地测试通过，为什么还不能保证今天的 key 和模型可用？
