# 09 工具宿主与声明式扩展点

**状态：旧五篇历史正文，未作为现行 09 验收｜永久免费 · Apache-2.0**

Rust loop已经决定下一步执行什么。现在把文件工具放到Node进程中，Rust仍掌握调用身份、预算、权限与结果采纳。这样后续TypeScript生态能力可以接入同一个Rein，而不另建一个拥有全部状态的循环。

## 先固定通用信封

旧M1 `rein-extension/0.1`围绕read_file、path和读取证据设计，不能直接声称支持任意工具。新版另建0.2，在invoke中使用通用arguments，在成功终态中使用通用result与evidence。完整契约位于 `contracts/extension-v0.2.md`；0.1历史入口继续保留。

宿主先发送ready，列出实际处理器的名称、参数与结果schema和消息上限。读取与搜索首次在本章交付；受控验证命令在13、补丁应用在16接入。计划中的工具不得提前写入运行时声明。

每条started、terminal和cancel都携带同一sessionId、requestId、taskId和callId。版本不支持、身份不匹配或结果形状矛盾时，core不采纳内容。工具声明描述能力，实际是否允许本次派发仍由core决定。

## 从一条真实读取观察完整过程

顺序为ready、invoke、started、terminal，再检查干净EOF与进程退出。只收到terminal还不足以证明成功；宿主可能随后输出第二个终态或异常退出。读取成功还应核对来源版本与实际内容，搜索也需要绑定本次查询和命中来源，不能接受一段没有依据的路径列表。

当前整合工程的0.2专项检查入口是：

```bash
cargo test --locked --manifest-path rust/Cargo.toml --test extension02
```

测试正在迭代；章节完成状态以实际审查记录为准。验收应同时包含有效宿主正对照，以及错误ID、版本、证据、重复终态、崩溃、取消与超大帧。坏宿主在ready阶段被拒绝，只能证明握手检查，不能替代后续终态反例。

## 一个在途调用

基础路线按确定顺序串行派发，每次至多一个在途调用。取消时向当前调用发送绑定身份的cancel，等待限定宽限期，必要时终止并回收进程；未派发的剩余调用只记事件。已派发后结果缺失属于未知，不自动重放。

Node宿主是受信任进程，不是操作系统沙箱。它必须通过声明式工具入口限制正常调用；恶意宿主的操作系统隔离不在本章承诺内。SDK、多版本演进和弃用策略留到20，本章只固定一个明确版本。

## 提示词示例

```text
请把当前读取和搜索处理器接入0.2通用信封，保持core掌握派发与采纳。
ready只声明实际实现的工具；校验每条消息身份、来源版本及最终进程状态。
先证明合法宿主走完整路径，再分别篡改终态字段验证拒绝，保留实际到达证据。
```

“派发与采纳”确定状态归属；“实际实现”避免提前宣布能力；“走完整路径”防止测试因早期错误而虚假通过。**试用状态：未试用。** 使用前请阅读[《提示词示例使用说明》](../prompt-examples.md)。
