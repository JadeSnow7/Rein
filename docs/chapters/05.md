# 05 让工具结果推动下一轮

本页保留第 05 章早期 TypeScript 循环的完整对照正文。当前主线入口是 [Rust core 版](./05-rust.md)：它负责权威的任务状态、工具策略和消息顺序；本页用于理解同一问题的历史实现与迁移差异，不是 Rust 页面的语言切换版本。读完后可回到本页继续比较，再进入第 06 章的 [Plugin 过渡](./06-plugin.md)。

模型只能看到请求中的消息，不能自行读取磁盘。本章把搜索与读取接成一个可观察循环：模型请求 `search_files`，程序执行它，把结果送回模型；模型再请求两个 `read_file`，两个真实文件内容进入第三次请求。本章附带最小前置：`ts/src/rein/contracts.ts` 的合同、`ts/src/rein/readonly.ts` 的只读工具、`ts/src/rein/adapters.ts` 的 OpenAI 兼容非流式适配器，以及 `ts/examples/ch05-loop.ts` 的离线适配器。`ts/src/rein/adapters.ts` 的 `createReplayAdapter` 接收 Anthropic 形状 JSON，经 `anthropicResponseToMessage` 转成 `ModelTurn`；这是离线格式适配，没有 Anthropic 真实网络入口。本章主演示仍是消费工具消息的动态离线 adapter。适配器实现 `ChatAdapter.complete`，再传给 `runAgentLoop`；这不表示前四章已经完整交付。

## 先做离线实验

所有命令从仓库根目录运行。新读者先确认 Node/npm，并在首次准备依赖时执行 `npm ci`；已经有锁定依赖时可跳过这一步。本章的跟做从下面的输入开始，目录中只有两份文件：

```bash
node --version
npm --version
npm ci
```

```bash
export REIN_CH05_DIR="$(mktemp -d)"
printf 'marker: README alpha\n' > "$REIN_CH05_DIR/README.md"
printf 'marker: NOTES beta\n' > "$REIN_CH05_DIR/notes.md"
```

依次运行：

```bash
npm run typecheck
npm run ch05:offline --workspace ts -- workspace "$REIN_CH05_DIR" single
npm run ch05:offline --workspace ts -- workspace "$REIN_CH05_DIR" multi
```

默认 `multi` 是三轮：第一轮搜索 `marker:`，第二轮读取搜索结果中的 `README.md` 与 `notes.md`，第三轮回答。输出 JSON 的 `answer` 是 `多文件摘要：marker: README alpha | marker: NOTES beta`；两个文件末尾的换行由 `printf` 写入，读取结果保留该输入，摘要显示时再去掉每段两端空白。`single` 直接读取 `README.md`。

## 接口与状态

`ts/src/rein/contracts.ts` 用接口描述消息、一轮模型结果和可替换适配器：

```ts
export interface Message { readonly role: Role; readonly content: string; readonly toolCallId?: string; readonly toolCalls?: readonly ToolCall[] }
export interface ToolCall { readonly id: string; readonly name: string; readonly arguments: Readonly<Record<string, unknown>> }
export interface ModelTurn { readonly message: Message; readonly toolCalls: readonly ToolCall[] }
export interface ChatAdapter { complete(messages: readonly Message[], tools?: readonly ToolDefinition[]): Promise<ModelTurn> }
```

`Promise<ModelTurn>` 让同一个循环接离线回放或真实 HTTP。两个工具 schema 分别声明字符串 `needle`、`path`，并声明不允许额外字段；`dispatchReadonly` 只检查当前工具名和所需参数，不等于完整的运行时 JSON Schema 校验。缺失文件返回 `path_invalid`，越界返回 `path_escape`。

下面是 `ts/src/rein/loop.ts` 中完整的 `runAgentLoop` 函数（imports、类型定义和 `dispatchReadonly` 的实现略去）：

```ts
export async function runAgentLoop(adapter: ChatAdapter, workspace: Workspace, prompt: string, options: LoopOptions = {}): Promise<LoopResult> {
  const maxTurns = options.maxTurns ?? 32
  const tools = options.tools ?? readonlyToolDefinitions
  const messages: Message[] = [{ role: 'user', content: prompt }]
  const events: LoopEvent[] = []
  for (let turn = 1; turn <= maxTurns; turn++) {
    events.push({ type: 'model_requested', turn, messages: structuredClone(messages), tools: structuredClone(tools) })
    let model
    try { model = await adapter.complete(messages, tools) }
    catch (error) { return finish(messages, events, 'failed', 'model_error', undefined, error instanceof Error ? error.message : 'model error') }
    messages.push(model.message)
    events.push({ type: 'model_received', turn, message: structuredClone(model.message), toolCallIds: model.toolCalls.map(call => call.id), text: model.message.content })
    if (model.toolCalls.length === 0) {
      if (model.message.content.trim().length === 0) return finish(messages, events, 'failed', 'empty_final')
      return finish(messages, events, 'completed', 'final_answer', model.message.content)
    }
    for (const call of model.toolCalls) {
      const result = await dispatchReadonly(call, workspace)
      events.push({ type: 'tool_result', turn, call: structuredClone(call), toolCallId: call.id, result })
      messages.push({ role: 'tool', toolCallId: result.toolCallId, content: result.ok ? result.output ?? '' : JSON.stringify({ ok: false, error: result.error }) })
    }
  }
  return finish(messages, events, 'failed', 'max_turns')
}

function finish(messages: Message[], events: LoopEvent[], state: Exclude<LoopState, 'running'>, reason: StopReason, answer?: string, error?: string): LoopResult {
  events.push({ type: 'stopped', state, reason })
  return { state, reason, ...(answer === undefined ? {} : { answer }), messages, events, ...(error === undefined ? {} : { error }) }
}
```

在 `ts/examples/ch05-loop.ts` 的回放适配器中，`multi` 分支的方法内摘录如下；它先消费搜索结果，再在下一次 `complete` 调用中生成 read calls，不能把两轮合并：

```ts
if (tools.length === 0) return turn('', [{ id: 'search-1', name: 'search_files', arguments: { needle: 'marker:' } }])
if (tools.length === 1) {
  const only = tools[0]
  if (!only) throw new Error('missing search result')
  const paths = only.content.split('\n').filter(Boolean).slice(0, 2)
  return turn('', paths.map((path, i) => ({ id: `read-${i + 1}`, name: 'read_file', arguments: { path } })))
}
return turn(`多文件摘要：${tools.slice(1).map(m => m.content.trim()).join(' | ')}`)
```

`await` 等待 `Promise`；`Role` 是字面量联合，optional 调用字段表达字段可能缺失。`readonly` 只提供编译期约束，运行时复制或不受类型检查的代码仍可修改对象；`structuredClone` 用于事件快照，避免后续 `push` 改写历史。

第二次请求只有 `search-1` 的结果，第二轮执行两个 read，第三次请求才同时有 `read-1`、`read-2`。下面只展示消息序列中的相关字段，省略其他字段，不是完整的顶层 JSON：

```json
{"role":"tool","toolCallId":"search-1","content":"README.md\nnotes.md"}
{"role":"assistant","toolCalls":[{"id":"read-1","name":"read_file","arguments":{"path":"README.md"}},{"id":"read-2","name":"read_file","arguments":{"path":"notes.md"}}]}
{"role":"tool","toolCallId":"read-1","content":"marker: README alpha\n"}
{"role":"tool","toolCallId":"read-2","content":"marker: NOTES beta\n"}
```

事件保存完整 messages、tools、模型消息、调用参数和结果，足够检查当前请求；它不是持久恢复系统。默认最多 32 轮；适配器错误、空回答和上限分别得到 `model_error`、`empty_final`、`max_turns`，末尾都有 `stopped`。

## 失败实验与 live

以下命令继续使用开头的 `$REIN_CH05_DIR`，从仓库根逐条运行：

```bash
npm run ch05:offline --workspace ts -- workspace "$REIN_CH05_DIR" recovery
npm run ch05:offline --workspace ts -- workspace "$REIN_CH05_DIR" empty
npm run ch05:offline --workspace ts -- workspace "$REIN_CH05_DIR" exhausted
npm run ch05:offline --workspace ts -- workspace "$REIN_CH05_DIR" limit
```

预期依次是：`recovery` 为 `state: "completed"`、`reason: "final_answer"`，先有 `path_invalid` 后读 README；`empty` 为 `state: "failed"`、`reason: "empty_final"`；`exhausted` 为 `state: "failed"`、`reason: "model_error"`；`limit` 为 `state: "failed"`、`reason: "max_turns"`。每次末尾均为 `stopped`。

真实调用也从仓库根显式开启。配置示意中的值需要替换为个人配置；只有显式使用 `--live` 才会发出网络请求，本章离线跟做不调用服务：

```bash
export REIN_BASE_URL="https://个人服务.example/v1" REIN_API_KEY="个人密钥" REIN_MODEL="个人模型"
npm run ch05:live --workspace ts -- --live "$REIN_CH05_DIR" "请搜索 marker: 并读取命中文件"
```

程序不自动加载 `.env`，运行前 export 三个变量；workspace 仍是同一个只含 README/notes 的 `$REIN_CH05_DIR`。live 只有 `completed/final_answer` 以退出码 0 结束，其余 `failed` 结果以退出码 1 结束；离线失败演示仍打印 JSON 并以退出码 0 结束。

## 练习

**05-1：多文件读取。** 运行 `npm run ch05:offline --workspace ts -- workspace "$REIN_CH05_DIR" multi`。验收第三次模型输入有两个与真实内容配对的 tool 消息，答案为 `多文件摘要：marker: README alpha | marker: NOTES beta`。

**05-2：缺失后恢复。** 运行 `npm run ch05:offline --workspace ts -- workspace "$REIN_CH05_DIR" recovery`。验收 `missing-1` 为 `path_invalid`，`ok-1` 随后读取 README，最终为 `final_answer`。

**05-3：停止边界。** 运行下面两条命令：

```bash
npm run ch05:offline --workspace ts -- workspace "$REIN_CH05_DIR" empty
npm run ch05:offline --workspace ts -- workspace "$REIN_CH05_DIR" limit
```

验收原因精确为 `empty_final`、`max_turns`，末尾 `stopped` 且无 `answer`。
