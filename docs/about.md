# 阅读指南

Rein 从一个 C++ Hello World 的生成与修复任务出发，逐步实现 Agent 周围的运行程序。我们先用 Python 看清模型请求、工具执行、差异审查和编译验证，再用 Rust 承担核心循环、边界与状态，最后把它放进一个能操作的轻量 IDE。

全书采用一种固定分工：第一至五部分由人确定架构、设计和验收条件，AI 编程助手编写代码，程序执行验收；第六部分再研究把设计也交给 Agent 需要哪些前提。01–03 只需知道配套程序按怎样的设计写成；从 04 起，你会亲自写设计卡，并用 Claude Code、Codex 等代码助手实现。

当前正式目录采用六部分、00–29。第一部分 00–03 有正文和配套程序；[04 Agent 的核心能力](./chapters/agent-capabilities.md)已有初稿，并把第一部分中不依赖模型协议的行为迁移到了 Rust。05–29 目前提供可达的规划入口，不代表已按新编号实现。完整路线和历史材料入口见[全书目录](./toc.md)。

## 从哪里开始 {#start}

先读 [00 我们要实现一个怎样的 Agent](./chapters/minimal-agent.md)，把编码任务写成明确的目标、允许路径和完成条件。然后按下面的顺序跟做：

| 章节 | 本章增加的能力 | 读完后可以观察什么 |
| --- | --- | --- |
| [01 Python 模型调用](./chapters/python-model-call.md) | 问候与完整编码任务 | 收到源码，人工保存、编译与运行 |
| [02 让 AI 读取代码与日志](./chapters/python-file-read.md) | 模型请求 `read_file` 和受限 Bash | 当前源码、日志与检查结果进入模型消息，形成待审查候选 |
| [03 终端代码助手](./chapters/python-suggestions.md) | 差异、用户决定、应用与验证 | 放弃不写；接受后备份、编译并核对输出 |
| [04 Agent 的核心能力](./chapters/agent-capabilities.md) | 能力地图；人写设计、代码助手实现的 Rust 迁移 | Python 与 Rust 在同一组样本上行为一致 |

第一、二章由读者手工保存源码；第三章的编辑入口在用户接受后才写入 `hello.cpp`。集成 CLI 默认使用离线教学替身；第一章最短 SDK 程序和安全请求入口使用真实服务，运行前需要配置。离线替身不具备通用理解能力，不能用它的正确输出证明某个模型一定能完成任务。

我们假设你能运行终端命令、读写简单程序。Python 虚拟环境、环境变量、JSON 和工具消息会在首次使用处解释，无需先学 Rust。[阅读 0](./readings/00.md)和旧 TS/Rust 补充材料可按需查阅，其中语言与编号按原版理解，不是新第一部分的必读前置。

## 语言和六部分怎样衔接 {#languages}

Python 用于第一部分的短流程。第 04 章先从 Codex、Claude Code、Gemini CLI 和 Copilot 的公开机制分析 Agent 核心能力；然后由你写设计卡和验收样本，让代码助手把第一部分的受限读取、差异、确认写入与编译验证迁移到 Rust，并用对照脚本检查两边行为一致。模型调用留到 05；05–08 依次加入统一消息、循环、停止和取消。旧 Rust hello 页面不能当作这次迁移。

第二部分完成可停止、可取消的 Rust CLI，第三部分再建立可信修改流程。第四部分是按依赖选用的计划、Skill、Hooks、MCP 与委派能力。第五部分把第三部分的成果接入 Web Studio 轻量 IDE，不要求先实现所有扩展。第六部分研究架构依据、设计记忆和持续演进效果。

旧页面上的 TS / Rust 切换用于原来的对照主题；Python 新章使用独立 URL，不参与旧语言切换。你仍可从[历史入口](./history.md)恢复旧教程、旧编号和快照。

## 怎样取得配套代码 {#code}

在拿到包含本轮新稿的仓库后，从根目录运行：

```bash
python3 python/hello_world/cli.py hello
python3 python/hello_world/cli.py generate
```

Python 环境与可选 SDK 的安装步骤见[第 01 章](./chapters/python-model-call.md)。当前三章代码、样本和测试集中在 `python/hello_world/`；旧 `python/part1/` 的只读样例和记录保留；`ts/`、`rust/`、`core/` 与 `runtime/` 保留已有实现，各自的检查范围以对应说明为准。

从 04 起，每章正式正文末尾附交给代码助手的提示词，并标明来源：作者实际使用、据设计反推或已试用，规则见[提示词示例说明](./prompt-examples.md)。章末的输入输出清单用于复查当前教学版本。不要把框架里的 F00–F29 或 S1–S6 自动当成 Git 标签；只有实际记录了代码、输入和结果的产物才可用于复现。旧 `ch01` 等标签仍指向历史版本，切换后不会得到新 Python 教程。

## 每章留下什么 {#evidence}

完成命令之后，我们还要检查输出是怎样得到的。读文件要看到本轮真实内容进入消息，差异要由原文件和候选计算，失败要有可区分的原因。第 03 章用文件摘要检查放弃后不变与提案过期，并区分接受写入和验证通过。

测试检查列出的程序行为，站点构建检查页面能否生成，离线回放检查受控响应怎样被解释。真实端点的可用性、模型建议的质量，以及新手能否独立跟做，需要另行验证。当前第一部分不把这些结论混在一起。
