# 第二部分：核心循环

**04 初稿；05–08 规划中。** 从第一部分的 Python 终端助手出发，把已有单任务行为整理为 Rust Harness core，再依次加入统一消息、连续循环、预算与取消。下面是写作目标，不表示代码或教学验收已经完成。

## 04 Agent 的核心能力 {#ch04}

先观察代表性编码 Agent 的工具、权限、状态和交付机制，提炼 Rein 需要的能力；再由读者写设计、代码助手实现，把不依赖模型协议的行为迁移到 Rust，并在同一组样本上对照 Python。[阅读第四章](../chapters/agent-capabilities.md)。

## 05 统一模型消息与工具协议 {#ch05}

让 Rust core 用稳定的内部消息表示模型文本、工具调用、调用 ID、工具结果和错误。服务商格式由适配器转换；不能让某一家 API 的字段直接成为工具权限合同。第 04 章保留的单任务行为是本章回归输入。

## 06 写出核心 Agent Loop {#ch06}

让上一轮真实工具结果进入下一次模型请求，直到最终回答或明确停止。先用有界读取和离线回放展示“搜索→读取→回答”，再检查删除或修改文件后下一轮是否随实际结果变化。

## 07 让循环适时停止 {#ch07}

分别限制模型回合、实际工具派发和重复动作；预算阻止的调用只留下跳过事件，不伪造工具结果。读者应能从计数和停止原因解释每次结束。

## 08 取消任务与观察运行过程 {#ch08}

在模型等待、工具执行与结果采纳的边界处理取消和截止时间，输出可解释的事件序列。迟到结果不能让已停止任务继续推进；终端退出与任务成功分别报告。
