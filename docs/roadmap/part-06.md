# 第六部分：架构设计与持续演进

**25–29｜规划中。** 以第五部分的项目基线为对象，连续改变设计要求，观察 Agent 是否在满足新要求时保持已有行为。单次文档练习只可校准方法，不能证明持续演进能力。

## 25 让 Agent 理解项目的架构 {#ch25}

从真实源码和运行入口建立模块、依赖与数据流地图，并对不确定处标注需要实测的假设。

## 26 让 Agent 做出有依据的设计 {#ch26}

比较候选方案的约束、接口与代价，把采用理由和未验证前提写成可复审的决定。

## 27 让 Agent 记住设计理由 {#ch27}

让后续任务能找到设计决定及其前提；当代码或约束变化时触发复审，而非自动把旧理由继续当作有效。

## 28 让 Agent 持续修改而不破坏系统 {#ch28}

在同一项目上连续输入新需求，让每轮真实产物成为下一轮起点，同时执行新要求检查和历史回归。

## 29 如何判断 Agent 真的进步了 {#ch29}

固定任务、模型、权限与预算等比较条件，区分新需求成功、历史回归、资源成本及无法判断的结果。
