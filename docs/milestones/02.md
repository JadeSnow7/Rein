# 阶段性汇总 1　极简 Harness

这一阶段接通一条可观察路径：模型提出只读动作，Harness 在受限工作区执行，真实结果回到下一轮，最后由结构化停止原因结束。第 05 章给出 Rust core 的单文件和多文件读取，第 06 章加入预算、重复动作、取消和截止时间，并开始接入 TypeScript plugin。旧 TS 页面与快照用于历史对照；00–04 的完整交付不由这份阶段汇总代为宣称。

本页的命令对应携带的 `chapter-snapshots/rein-ch06.tar.gz` 文件树快照。需要恢复时，先阅读[阅读材料 2](/readings/02.html)，再从书仓库根目录解包到新的临时目录，进入其中的 `rein-ch06`；不要覆盖自己的工作区。首次运行在该书根执行 `npm ci`，Rust 则使用 `rust/Cargo.toml`。

## 单文件任务

从书仓库根目录准备自己的绝对目录：

```bash
export REIN_STAGE1_DIR="$(mktemp -d)"
printf 'marker: ch06 alpha\n' > "$REIN_STAGE1_DIR/README.md"
printf 'marker: ch06 beta\n' > "$REIN_STAGE1_DIR/guide.md"
npm run ch05:offline --workspace ts -- workspace "$REIN_STAGE1_DIR" single
cargo run --manifest-path rust/Cargo.toml --example ch05_loop -- workspace "$REIN_STAGE1_DIR" single
```

`single` 会提出一次 `read_file`，工具结果包含 `marker: ch06 alpha`，下一轮才生成最终回答。两种语言都把路径限制在 `Workspace` 根目录内；绝对目录也避免 npm workspace 或 Cargo 改变 cwd 后读错位置。

## 多文件任务

```bash
npm run ch05:offline --workspace ts -- workspace "$REIN_STAGE1_DIR" multi
cargo run --manifest-path rust/Cargo.toml --example ch05_loop -- workspace "$REIN_STAGE1_DIR" multi
```

第一轮是 `search_files`，第二轮根据搜索输出产生两个 `read_file`，第三轮回答 `多文件摘要：marker: ch06 alpha | marker: ch06 beta`。Harness 的关键是把工具结果作为下一轮消息，而不是把答案写在工具脚本中。删除 `guide.md` 会改变搜索和摘要；越出工作区的路径会得到结构化错误。

## 停止控制

```bash
npm run ch06:offline --workspace ts -- normal "$REIN_STAGE1_DIR"
cargo run --manifest-path rust/Cargo.toml --example ch06_loop -- normal "$REIN_STAGE1_DIR"
npm run ch06:offline --workspace ts -- budget "$REIN_STAGE1_DIR"
npm run ch06:offline --workspace ts -- tool-zero "$REIN_STAGE1_DIR"
npm run ch06:offline --workspace ts -- zero "$REIN_STAGE1_DIR"
cargo run --manifest-path rust/Cargo.toml --example ch06_loop -- budget "$REIN_STAGE1_DIR"
cargo run --manifest-path rust/Cargo.toml --example ch06_loop -- tool-zero "$REIN_STAGE1_DIR"
cargo run --manifest-path rust/Cargo.toml --example ch06_loop -- zero "$REIN_STAGE1_DIR"
```

正常场景先搜索再读取两个文件，`reason` 是 `final_answer`。`zero` 的模型请求数为 0，原因是 `max_turns`；`tool-zero` 仍请求一次模型但所有工具跳过；`budget` 执行第一个工具、跳过第二个。CLI 退出码为 0 只表示它打印了 JSON，必须查看 `state` 和 `reason`。

## 失败原因

```bash
export REIN_STAGE1_EMPTY="$(mktemp -d)"
printf 'unrelated\n' > "$REIN_STAGE1_EMPTY/other.txt"
npm run ch06:offline --workspace ts -- normal "$REIN_STAGE1_EMPTY"
cargo run --manifest-path rust/Cargo.toml --example ch06_loop -- normal "$REIN_STAGE1_EMPTY"
```

没有匹配文件时本章回放报告 `model_error`，没有 `answer`。模型适配、传输或解析异常也属于 `model_error`；工具失败以结构化工具结果反馈，空最终文本是 `empty_final`。取消是 `cancelled`，整体截止时间是 `timeout`，重复动作和工具额度各有独立原因。区分这些结果，调用方才知道重试、补输入还是结束。

## 综合练习

1. 改写 `README.md` 的 marker，分别运行 TS/Rust 的 `multi`，确认摘要随真实内容改变。
2. 运行两种语言的 `duplicate`，检查不同调用 ID 仍因同一规范化动作被拦截。
3. 运行 `cancel-before`、`cancel`、`cancel-at-return`、`cancel-between-tools`，记录模型/工具计数分别为 0/0、1/0、1/0、1/1。
4. 同时查看 `events` 与 `messages`：真实工具结果两处都存在，被跳过调用只有 `action_skipped`。

本页只覆盖单/多文件循环与停止控制；更复杂的上下文、修改、持久化和并发所有权留在后续阶段。
