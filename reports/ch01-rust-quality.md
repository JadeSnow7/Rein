# ch01 Rust 四层质检

本报告对应主线程最终复核后的正文，而非子代理首稿。执行日期为 2026-09-13。

## L1 硬性规则，通过

正文自动扫描，禁用词、结构套话、空泛工具名均为 0 处；排除用户指定标题、合法代码、URL、HTML 锚点和内联代码后，禁用标点为 0 处。正文保留一级标题，步骤用数字段落和 span 锚点，不用成片小标题或项目符号堆叠。

标题中的破折号遵循用户明确指定，程序中的引号和冒号遵循代码语法。未使用原作者身份、署名或公众号推广尾部。

## L2 风格一致性，通过编辑复核

从「在ChatGPT中」的输入场景与疑问进入，包含独立短段、长短句变化、读者直呼和疑问转向。转场围绕 hello 主线展开，使用「你想想看」「我觉得」「说真的」「很多朋友可能不知道」「回到这次 hello」「这块需要注意一下」「其实吧」「怎么说呢」「顺着上面的」「说实话」「我一直觉得」等表达。包含对第一次安装、报错或无法判断网络结果的承认，不编造作者亲历。

## L3 内容质量，通过编辑复核

环境与 Git 快照、官方 API key 入口、SDK 示例、非固定输出与退出码、逐层错误代码、结果记录、四项练习都有具体动作。async-openai 0.29.6 的 API 错误不完整保留 HTTP 状态，正文明确依赖 code/type 的诊断边界。

最简示例与完整入口各自说明作用；代码摘录标明为片段或引用源文件，不称未编译的散落片段为完整程序。Hello World 的入门意象与开头问候呼应，不强加不相关的文化故事。学习成本和失败点落在依赖安装、配置与网络上。

## L4 活人感，通过编辑判断

主线程通读并改写了首稿中的说明书式堆叠，保留朴素的问候目标、对初学者报错困境的理解和逐步解释。这个判断属于编辑评价，不是自动工具能证明的文风结论，作者可继续按自己的声音定稿。

## 验证范围

四层文风检查不能代替代码验证。最终编译、测试、命令行与页面检查证据见 [交付验收记录](ch01-verification.md)。没有发起真实模型请求，也没有发布远程站点。
