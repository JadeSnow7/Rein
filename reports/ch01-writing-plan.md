# ch01 写作路线与补全判断

用户确认于 2026-09-13，两个版本指 TypeScript 与 Rust，采用相同教学路线，各有正文和源码。

## 选题判断

采用方法教学与产品体验结合的写法。H 来自 ChatGPT 输入框背后发生了什么的疑问，K 来自可完成的一次 SDK 调用和定位失败的办法，R 来自熟悉聊天产品但对终端和报错陌生的读者处境。三项都能落到本章具体动作，不靠编造作者经历或夸张模型效果。

使用 khazix-writer 的短段落、口语转场、疑问推进与首尾呼应。标题按用户指定保留「HelloWorld——从模型调用开始」，代码和 URL 保留合法语法，书籍正文不附原作者署名或公众号推广尾部。

## 补全后的教学路线

1. 第一段从「在ChatGPT中」开始，让读者回想输入和回答之间的空隙。只以产品交互引出问题，不虚构 ChatGPT 内部实现。
2. 明确最小任务。命令行、非流式 Chat Completions、单条 user 消息 hello、非空回答、成功退出；读者确认确实回应问候。
3. 环境准备。克隆仓库、确认语言工具链、切换本章快照、按锁文件安装依赖。每组命令写明目录，解释 detached HEAD 和已有修改的保存。
4. 获取凭据。提供低成本官方服务入口、创建 key 与查看余额的大致流程；API key、base URL、model ID 成套配置。链接当时官方模型与价格页，不承诺赠送额度和最低价。
5. 最简 SDK 示例。先把完整短程序给读者，解释 SDK 代办的请求组织与响应读取。TS 官方 SDK 与 Rust 社区 SDK 明确区分来源。
6. 观察结果。运行命令、非固定示意输出、退出码检查。区分 HTTP 成功、结构有效、回答有意义。
7. 逐步处理失败。每一层跟着一次请求的行程推导，再给对应代码。区分环境/SDK安装、本地配置、连接与超时、401/403、404、429限流与额度、5xx、JSON与空内容。
8. 结果与练习。四个练习分别修改 prompt、缺失配置、本地受控失败、真实调用记录。TS 与 Rust 练习编号及验收问题相同。

## 实现边界

每次命令只发起一次模型请求，显式关闭 SDK 自动重试，等待上限 30 秒。超时不说明服务端未执行。不在首章引入多轮、工具、自动恢复或抽象协议合同。

保留旧 TS 手写客户端与 fixtures，将其讲解移到进阶页，主线不以离线回放作为第一步。建立 Rust 正式 Cargo 工程，阅读 0 独立示例保持独立。语言按钮启用真实 Rust 正文入口，目录与阅读指南同步。

历史 ch01 标签不能承载新 SDK 教程。保留原标签，新增本地 ch01-helloworld 快照；远程未发布时明确说明，不能假装新克隆仓库已能取到该标签。
